# 2026-10-25 联调总结：边界条件

范围：本轮浏览器、Gateway、AgentBrain、QwenMock、OLS 联调。主要证据为用户反馈、`docs/works/历史档案/前端和AgentBrain联调流程-原文.md`（原 `前端和AgentBrain联调流程.md`）的 10 月 25 日复测记录，以及当前源码/回归测试。下文区分现场遇到的问题和代码防线；不将所有自动化分支都宣称为已人工复现。本次只整理文档，没有重启服务或重复运行测试、xhigh。

## 1. 会话归属与异步竞态

| 条件/表现 | 原因或风险 | 当前处理与验收点 | 证据 |
| --- | --- | --- | --- |
| 新建后立即发消息，报 `the selected conversation does not belong to the active Agent session` | 显式新建、自动场景绑定、sessionState 对账、历史创建同时发生，前端选中历史行可能还指向旧 session | Gateway 串行协调转换并丢弃过期结果；前端发送前等待权威 session 和历史绑定完成。有效提交的历史 session 与当前 session 必须相同 | 用户报告；会话竞态两轮复测；`test_gateway_sessions.py`、`session_identity.test.ts` |
| 消息记录请求等待期间切换会话或场景 | 命令随后才提交，可能落入新会话 | 发送前固定 sessionID、conversationId、完整场景；异步等待后变化则停止发送；Gateway 对过期 session 返回 409 | `submitAgent`、`jobs`、会话身份测试 |
| `/startTask` 尚未返回时切换到另一会话 | 迟到的任务受理把新会话误锁定，或回复写到新会话 | job 保留创建时 conversation_id/session；agent_owned 记录在任务所属 session；只有匹配当前选择的响应更新当前面板 | 联调记录、`test_gateway_agent.py` |
| 快速连续新建/切历史，旧 HTTP 响应晚到 | 旧响应回滚新选择 | 前端选择代次、session 刷新版本和 Gateway 转换代次用于丢弃过期结果 | `test_gateway_sessions.py` 中 late/overlapping/fresh reconcile 用例 |
| 同一 Brain session 对应多条历史行 | 按 sessionID 搜索第一行会写错历史 | 显式新建始终建独立历史行；任务使用 conversationId 归属，保护旧行按历史行 ID 判断 | 用户问题相关修复；同 sessionID 重用回归 |

## 2. 会话场景串绑与相机边界

### 2.1 用户报告的复现链

1. 会话 1 使用含物体的场景执行任务。
2. 通过资产面板选 `ur5e_table_empty` 创建会话 2。
3. 会话 2 发送“把苹果放进盒子里”，得到 `grounding_missing: apple`。
4. 切到会话 1 再切回会话 2，曾出现会话 2 场景变成会话 1；会话 2 运行中创建会话 3，曾出现新会话继承会话 2 场景。

语义失败本身是合理结果，场景串绑是错误。关键问题在会话转换窗口：新 session 已存在，但旧历史行仍选中，旧场景上报、相机重绑和历史创建交错，可能把“当前场景”写进错误的历史行。

当前修复使用显式转换标记记录旧基线、预期目标、受保护历史行和相机；历史激活先恢复 Brain 绑定，再恢复该行快照。10 月 25 日记录中的复测结果为：会话 2 往返切换后仍是 `scene_id=1 / 8 objects`；会话 3 独立为空场景 `scene_id=0`；未再出现 conversation_session_mismatch。Gateway 对应提交为 `eb344ec`，前序相机/场景修复为 `5ce5f7d`、`6c97d67`。

### 2.2 相关分支

| 边界 | 当前规则 | 不能出现的结果 |
| --- | --- | --- |
| 新 session 创建成功，但新历史行尚未创建 | 旧历史行保持受保护；新场景和新绑定不写回旧行 | 会话 1 被改为会话 2 的场景 |
| 新建空对话时仍收到旧场景基线上报 | 识别过渡基线，等待目标场景及最终绑定 | 把旧场景当成新空对话的初始场景 |
| 新对话目标与当前场景不同 | 不继承旧 camera_id，允许先以 null 建 session | 空场景仍绑定旧场景相机 |
| 新场景没有相机 | 清掉旧候选/绑定；允许无相机会话，由具体任务报告能力问题 | 新建入口因候选为空永久卡住，或使用旧相机截图 |
| 同一场景稍后才报告相机候选 | 必要时自动新建绑定可用相机的 Brain session，并同步当前历史 | 已有相机却一直保持无相机；旧历史被修改 |
| 自动重绑被 Brain 拒绝，甚至连续拒绝 | 保留待重绑状态，下次同步重试；重试前后旧行保护均不能提前撤销 | 首次失败后忘记重绑，或失败重试改写旧行 |
| 自动重绑成功早于历史行创建 | 转换标记跟随最终 session，旧历史继续受保护 | 成功回包也导致旧记录串绑 |
| Brain 返回与此前相同 sessionID | 仍以 conversationId 区分新旧历史 | 认为 sessionID 未变所以无需保护旧行 |
| 激活历史时目标场景上报先到 | 保护离开的历史行，完成激活后才同步目标行 | 切换动作反过来改写原历史 |

这些分支由 `tests/test_gateway_sessions.py` 的 delayed report、camera rebind、same-session-id、history activation 用例覆盖；并非每一条都有独立人工抓包。

## 3. 场景语义与成功判据

| 场景/指令 | 合理结果 | 联调注意事项 |
| --- | --- | --- |
| `ur5e_table_empty` 中要求把苹果放入盒子 | `grounding_missing: apple`，任务失败 | 场景没有苹果；不能通过返回固定成功来掩盖语义失败。失败不应破坏历史场景绑定 |
| 只有苹果、没有篮子的场景做放篮子任务 | grounding 缺失目标 | `ur5e_table_apple` 不能作为苹果和篮子都存在的用例 |
| 排序场景 `ur5e_table_sorting` 执行“把苹果放进篮子里” | 已记录 `plan_ready`、六步技能计划、“计划已生成，尚未执行” | 计划成功不等于机器人执行，场景版本可以不变 |
| 排序场景执行“删除香蕉” | 已记录 `scene_updated`，v3/15 objects → v4/14 objects | 应检查提交回执、对象数量与版本，不只看任务文案 |
| 全空 `scene_id=0` 发送“增加一个苹果” | 可触发 Brain 生成初始场景并提交 | 与资产库中的“空桌面场景”不同；后者仍有桌子、机器人等对象 |
| 全空场景发送“把苹果放进盒子里” | 当前资产库可能返回 `asset_ambiguous` | basket 存在蓝/白两个模型，不能把歧义当链路不通；空场景正向验收用“增加一个苹果” |
| 不支持的平台/关节资产 | 受理前返回具体 4xx，例如 `web_platform_profile_unsupported` | 不伪装为 502；未受理不得留下 job 或永久 agent_owned |

QwenMock 用于固定可处理的模型输出。当前 Brain 的公开结果为 `executed:false`；联调证明的是会话、推理、计划和场景提交链路，不是实机运动完成。

## 4. 租约、后台任务与关闭浏览器

| 边界 | 当前处理/验收 |
| --- | --- |
| 同一 session 已有非终态任务 | 后续新任务返回 `task_busy`；同幂等键重放应返回原任务 |
| 任务受理后、租约尚未建立 | 已进入 agent_owned；不能把“没有 lease”解释为可以随意更改任务现场 |
| 资产切换确认时旧任务仍执行 | allowActiveTask 路径保留旧 session 的租约/快照，旧任务继续；不存在自动取消 |
| 顶部 New conversation 与资产确认入口 | 当前前者不带 allowActiveTask、后者带 true；租约存在时可能行为不同，不能混为一个入口 |
| 旧任务切到后台后需要读世界或提交 | 使用所属 session 上下文、快照及 CAS；提交不得覆盖新前台场景 |
| 旧后台任务还需要 captureScene/get2DAABB | 返回 `session_browser_not_active`，不能借用前台另一场景图像；“后台继续”不保证一定成功 |
| 刚发送即关闭浏览器 | 未取得租约、场景或所需像素时可能失败；具体取决于关闭发生在哪一步 |
| 已取得租约及所有必要输入后关闭 | 可继续计算；满足证据条件可对会话快照提交，重开后恢复最新场景。若后续仍需新图像则不能保证成功 |
| browser.request 发出后无回答 | 可能为 504 BROWSER_TIMEOUT；迟到响应被丢弃，不能据此认定写入没发生 |
| commit_unconfirmed 期间新建/切历史 | 转换锁覆盖提交等待；前后均检查未确认提交，拒绝绕开 |
| releaseSceneLease keepLocked=true 或释放确认失败 | 保留 quarantine/不确定状态；任务失败不等于已安全解锁 |
| 恢复后台隔离会话 | 可以带隔离证据恢复到前台用于取证，但恢复完成前不能再离开或发新任务 |
| 正常终态且无 lease/quarantine | Brain/Gateway 恢复 setup；语义失败也不能让资产面板永久锁死 |

不确定状态通过 `/queryWorldCommit`、现场摘要和 `/resolveUncertain` 取证。HTTP 200 的 `kept_locked` 仍是保锁；重启、刷新、新建会话都不是安全解锁证据。

## 5. 刷新、重连与重启不是同一个边界

- **页面刷新或关闭重开，Gateway 进程仍在**：先 GET `/getWorld` 和活动历史，再 hello/state_sync。不能将浏览器初始化的空世界先上报，覆盖已有现场。终态回复由 Gateway 写入所属历史，按 role + turnId 去重。
- **WS 断开重连**：重新报告场景、查询 sessionState，按 conversationId 补取任务；旧历史的任务返回不得污染当前面板。重连丢帧通过 REST 补齐，不增加浏览器对 Brain 的轮询。
- **旧标签页仍打开**：一个浏览器绑定仍占用现场；第二个标签页不应抢先回答 getWorld 并覆盖现场。复测使用独立 profile 时也要确认旧标签页已断开。
- **Gateway 重启**：当前 conversations、jobs_state、session_contexts 为进程内状态；GatewayState 和事务回执另有持久化，不能因为代码注释写了“持久化”就承诺历史跨服务重启保存。启动时对无锁状态有清理逻辑，带锁/隔离必须保留恢复证据。
- **仅 Brain 重启**：Gateway 保留的 session 可能不再是 Brain 活动 session。setup 状态读取和任务提交前会对账；缺失/不活动可以恢复或重建，uncertain 不得自动绕过。
- **整套干净复测**：使用 `tools/restart_stack.ps1 -Build` 重启 OLS、QwenMock、Gateway、Brain，备份并清理运行态；`-KeepState` 不代表干净状态。每轮重启要求用于重新联调，本次文档整理不触发测试。

## 6. 版本、摘要与提交边界

| 边界 | 约束与结果 |
| --- | --- |
| 同 scene_id，版本相同但内容变化 | 依靠 scene_sub_version 与摘要判别，不能只比较 scene_version |
| setup 本地增删 | 只推进 scene_sub_version；灯光/辅助显示等渲染设置不进入文档摘要 |
| 普通 updateWorld 与 strict commitWorld | 普通写入沿用当前版本推进；strict 使用候选版本，不能二次自增 |
| commitWorld 候选 | 同场景版本必须旧版本 +1，子版本归零；从初始 scene_id=0/v0 生成场景有初始化分支，但严格提交仍要求 v1 |
| 未知组件/字段、默认值回退 | 保留原始文档用于摘要；不能把类型视图的补默认值写回原文后再比摘要 |
| 重复 clientRequestID | 同 session、相同 command/scene 请求体返回已有任务；不同内容返回 request_id_reused |
| 重复 transactionID | 同候选摘要读原回执，不重复执行；不同候选拒绝 |
| 部分对象被拒绝 | 普通导入可按对象报告；strict commit 不能部分落地 |
| 超时或回执落盘失败 | unknown 不是 rejected，也不是 committed；保留锁并取证，不能盲重发写请求 |
| ID 分配 | 对象 ID 水位从现场/写入提升，已占用或已释放 ID 不复用；scene/model/robot 的资产 ID 空间不能混用 |

对应证据：`tests/test_commit_world.py`、`test_gateway_state.py`、`test_digest.py`、`test_scene_lease.py`，前端 `world.test.ts` 和 `scene_requests.test.ts`。

## 7. 相机、健康与响应形状

| 条件 | 当前判据 |
| --- | --- |
| 相机帧来自旧场景、错浏览器，或正在播放 | 比较 browserID、四元组和 playback_state；拒绝 camera_frame_scene_mismatch |
| PNG 截断、尺寸不一致；RGBD 深度长度错误 | Gateway 做封包完整性校验，Brain 继续校验；不能把有 base64 当成有效采集 |
| 场景提交后还拿租约最初快照校验新图像 | 会错误判 scene changed；Brain 采集及最终核验读取提交后的当前现场 |
| OLS 首次全目录检查较慢 | 健康探针不能同步等待长目录遍历；当前使用启动检查/后台刷新及缓存结果，避免超过 Gateway 三秒健康期限 |
| 未建立 Brain session 时 browser=not_bound | 与首次绑定过渡区分；当前 Gateway 有在线浏览器时对相应健康结果作就绪处理，不能仅靠状态栏证明所有协议环节已完成 |
| 服务健康暂时失败 | 不直接把运行任务标失败；任务状态由任务查询独立决定 |
| 任务状态名变化 | 原样显示 state；只用 terminal 布尔判断结束，不按“任务完成”字样猜测 |
| Brain 查询任务 404 | Gateway 将该任务收敛为失败；一般是任务已不可查，不能继续无限轮询 |
| 连续轮询失败 | Gateway 连续五次错误后按失败收敛；这是传输层收敛，不证明 Brain 已取消或安全释放租约 |
| Brain artifacts 为对象，Gateway 只识别数组 | 当前任务视图可能显示空 artifacts；命名下载代理仍存在。此次源码核对发现并记录，未在文档任务中修改代码 |

最后一项及入口差异属于当前实现限制，不作为已经修复的问题。健康状态和 HTTP 200 也不能替代任务归属、场景四元组、租约与回执的检查。

## 8. 最小人工回归检查表

若后续重新复测，每轮先重启整套服务，再检查：

1. 加载排序场景后立即发送计划指令；历史仅一条，session 与历史行一致。
2. 新建空对话后立即发送“增加一个苹果”；场景成功初始化，旧历史不变。
3. 会话 1 → 资产面板空桌面新会话 2 → grounding_missing → 往返切换；会话 2 仍是 scene_id=1。
4. 会话 2 运行时经允许的切换路径建会话 3；会话 3 绑定其目标场景，旧任务结果归属旧行。
5. 刷新、关页重开、后台完成分别检查消息不丢不重、场景正确；需要图像的任务断线失败与已取得输入的后台成功分开判断。
6. 普通终态后无 lease/quarantine 才恢复 setup；有不确定证据必须保锁，不以新建或重启绕过。
