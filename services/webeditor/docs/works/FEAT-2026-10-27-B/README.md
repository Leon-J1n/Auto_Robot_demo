## 任务卡原文

### FEAT-2026-10-27-B —— UI 优化第三轮：撤下三处界面物 + 文案只说结果 + 新建会话不再报假失败（Q124/Q125/Q126；新卡 ㉞；依赖 FEAT-2026-10-26-A、FEAT-2026-10-20-A、FEAT-2026-10-24-B）

- **起因（用户原话，同轮七条）**：「1.删除渲染窗口左下角的 Three.js WebGL 字样和图标 2.删除 Agent Operation 子面板 3.删除 Agent 窗口中输入栏下方的独立的 Text 字样 4.Agent 面板的标题行现在是一行 ASSISTANT + 一行 Scene Agent，改为只有一行 Agent 5.当 Agent 面板中对话内容为空时……修改为一个图标+Agent+向Agent发送命令。6.删除所有有关于"仅渲染层"或者其他类似的描述，对于这些需要修改的描述，用最简洁的话让用户明白其作用（如 光照已切换）。7.Agent 面板的新建会话有个 bug，直接点击新建会话会提示会话切换被取消，但实际上它正常新建了会话并切换到了新会话。删除这个提示。」决议记规格 **§13.40（Q124/Q125/Q126）**，新增正文 §7.5（面板标题行与空态）与判据 §12.23，就地修订 §4.8.1、§7.1（截图／录制两条）、§9.3（末条删键）。
- **Q124 文案侧（六处）**：`截图已复制：<宽>×<高> 像素`、`光照已切换：<预设名>`／`光照已跟随场景`、`投影阴影已开启`／`已关闭`、`物体包围盒已显示`／`已隐藏`，工具栏五处 `title` 的括注（`editor layers left out`、`render layer only, never the scene`、`never captured`、`local, not reported`、`browser local, never reported`）一起撤。**判据一字未动**：§4.8 的 ③ 类分类、§12.16/§12.19/§12.20 的负控制原样留着 —— 搬的是这句话的位置，不是这件事的真假。两处取舍记进 §13.40：不做"详细模式"第二套话术（判据也要跟着两套）；`光照已切换：` 后面保留英文预设名（那是下拉框里同一段文本的复述，翻译等于给用户两个名字）。
- **Q125 撤物侧（三处宿主 + 两行并一行 + 空态）**：`.viewport-badge`（`Three.js WebGL` 角标）、`.operations` + `.operations-content` + `#operation-count`（Operations 子面板）、`#speech-status`（输入行那个 `Text`）连模板、委托分支与 `styles.css` 三条规则一起删；`<header class="agent-header">` 从 `<div><small>ASSISTANT</small><h2>Scene Agent</h2></div>` 收成单个 `<h2>Agent</h2>`；空态两行文字改 `Agent` / `向Agent发送命令`（图标 `<i data-lucide="bot">` 与 `.agent-empty` 结构不动）。**键的处理分两路**：`viewport.rendererBadge` **删键**（85 → **84 键**，§9.3 的 M6-3 死键规则：既无代码引用又无 `data-feature` 宿主，`original_config` 里也从来没有这一条 ⇒ 不破坏跨构建方契约），`agent.operations`／`agent.input.speechStatus` **留键**（§5.9 的 Agent 占位策略，`parity_inventory.py` 报 `unreferenced` 而不是死键）。**两处版式连带**：`.agent-header h2{margin:0}`（全站 `h2` 那条 `margin:2rem 0 0` 是为两行写的，一行之后标题被推到中线以下）、`.agent-panel form>div{justify-content:flex-end}`（mic/send 不再靠那个 `<span>` 撑位）。**一处语音后果**：`Text`／`Listening…` 那块常驻 `<span>` 撤下后，"正在聆听"改走 `showAgentToast`（瞬时状态不留常驻 DOM）。
- **Q126 那个假失败**：`POST /sessions` 于 **7.203** 答出新 id `35a22f70…`，`createSession` 等待的那次读回（版本 6）在 **7.409** 落地时**被自己丢弃** —— 同一次点击里 `applyWorld(resetDocument)` 的 `scene.applied` 回声在 **7.207** 又调度了版本 7，"`sessionRefreshVersion` 最后调度者赢"于是让 6 号作废、7 号到 **7.511** 才落地；那句后验 `state.session?.sessionID !== view.sessionID` 跑的时候浏览器"相信"的还是 `0c222f66…`（上一个会话），**而同一轮的读回本身已经证明 Gateway 绑上了新 id**。修法是**两处一起做**：**① `refreshSessionState()` 串行化**（新读回链在上一次之后，丢弃规则保留、落地次序改由调度决定；请求数不增，`readCurrentSessionState` 本来就先 `fetch` 再判戳）；**② 撤下"信念 id 必须等于这次 POST 返回的 id"**（对刚由这次 POST 建立的绑定，POST 才是权威；能取消这次迁移的只有**更新的用户选择**，`conversationSelectionGeneration` 两处各判一次）。只做 ① 则后验判据仍会在别的时序里误伤，只做 ② 则其他入口仍会被"最后调度者赢"打断自己刚排好的读回。**顺带一条 dev 侧缺陷**：`editor/vite.config.ts` 的 `callerRoutes` 不含 `/sessions` ⇒ 开发模式下点新建会话直接 404（**坑 3** 的复发），这条竞态在 dev 里根本测不到；本卡补进代理，取证仍走一次性栈。
- **单测**：**一例都不新增，也不该新增** —— 界面文案、DOM 宿主与"这次点击自己排了两条读回"的时序都没有单测面（`main.ts` 不导出可测函数，`session_state.test.ts` 钉的是 `newSessionView`／`lightingFreeze`／`mergeSessionPhase` 这些纯判据，本卡一条都没碰）。于是 `npx vitest run` **492 例 / 17 文件**逐位不变**本身就是判据 ①**（与卡 ㉛ 同一条处置）：它若红了，说明这条"看起来只是界面"的改动越界动了逻辑。
