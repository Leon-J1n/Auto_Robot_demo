# 2026-11-09 独立本地流式语音

## 原因
用户批准浏览器→Gateway→独立本地语音服务方案，在 NativeService 下新建项目，优先 CUDA、不可用时 CPU。

## 做了什么
新项目 streaming-speech：Python 3.11 独立环境、sherpa-onnx 1.13.3、中文 14M Zipformer transducer 官方模型、下载校验器、配置、启动脚本、健康检查、WebSocket 流式识别。GPU 子进程探测并辨认原生静默 CPU 回退，无 torch。

前端以 AudioWorklet 取代浏览器 Web Speech，PCM16 重采样、分片、尾片收尾、segment 替换和跨句累积；专用 /speech 经 Gateway 转发，保持各连接隔离。发送前等待 done，失败保留文字，防重复发送，保留回车/麦克风焦点行为。规格 §7.6/§9.1、两份 types、常量配置、Vite 代理和发布清单同步。未修改 Agent、World 或用户已有 changelist。服务项目单独 Git 仓库，本仓提交网关与前端。

## 验证
浏览器专项 10 项：重采样分片连续性、Worklet 尾片、临时文本替换、等待 done、超时/错误释放、麦克风拒绝、启动期间停止、发送按钮/输入框回车/麦克风回车与非语音发送。完整前端 690 项/23 文件、类型检查、构建通过（JS 905.82 kB，较前次 +4.71 kB；CSS 22.07 kB 不变）。语音服务 4 项：真实模型中文样例、CUDA/CPU 判据、连接隔离、无效 PCM/连接限制。Gateway relay 2 项，打包 10 项。真实服务→Gateway WebSocket 全链通过一次性端口回放官方录音，输出“对我做了介绍那么我想说的是大家如果对我的研究感兴趣”。当前安装为 CPU wheel，真实 CPU 回退已验证；没有可用 CUDA 构建的真实 GPU 验证，未直接录制用户麦克风。

网关路由 12/13，通过前基线同为 12/13：既有 per-link 配置 false 与内置 true 差异，未修改。audit_parity.py 在旧 viewer/缓存世界审计段等待不返回，已终止本轮进程；HEAD 基线设置 20 秒边界同样超时，未报告审计通过或提交派生 probes。模型及 .venv 不入库。未重启用户 8000/8080/8099/8500 服务。负控制撤销等待最终结果与音频转发，确认对应测试失败后恢复。生成 dist，实际运行需启动语音服务并重启 Gateway，再强制刷新网页。
