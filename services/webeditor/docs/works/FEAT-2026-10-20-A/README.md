## 任务卡原文

### FEAT-2026-10-20-A —— 视口截图按钮：把「此刻的画面」去掉一切辅助图层送进剪贴板（Q108；新卡 ㉗；依赖 M1-4、M5-2、FEAT-2026-10-17-C、FEAT-2026-10-19-D）

- **起因（用户原话）**：「添加一个截图按钮，用于截取当前渲染窗口中的内容（不含工具指示器、灯光占位模型等内容），截取后将截图送入剪贴板」。决议记 **§13.33（Q108）**，正文**就地修订 §4.4**（末条整段：截的是**编辑器自己的 orbit 相机此刻所见**，与上面那条 `/captureScene` 是两件事 —— 后者是对外通道、按某个 `Camera` 组件的光学系离屏渲染、结果交给发起调用的客户端；本条是**纯本地动作**，产物只进剪贴板）、**§7.1**（工具栏那个按钮 + 五条子项）、**§9.3**（`features.json` **84 → 85 键**，新键 `viewport.snapshot` 的宿主就是这个按钮 ⇒ 判 `literal`，与 `viewport.exportScene`/`viewport.focusSelection` 同族），新增验收 **§12.16** 七条（①-⑥ 判据 + ⑦ 不做的事）。
- **三条取舍，每一条都是"少写一套东西"**：**① 排除判据一个字都不重写，直接复用 §4.4 那条现成的通路** —— 用户点名的"工具指示器、灯光占位模型"在这一族里**早就存在**（选中描边 `Box3Helper`、gizmo、段末幽灵 `userData.ghost`、轨迹路点 `userData.waypoint`、相机视锥线、灯光占位球与类型标签，地面网格与坐标轴靠 `isEditorOnly()` 里 `type.endsWith("Helper")` 那条兜住），`renderer.ts:hideOverlays()` 按 `isEditorOnly()` 遍历 `scene` 把**当前可见**的编辑层临时按下、`finally` 只恢复自己关过的那些（**坑 75**）。**两份清单必然分叉**，而 Q105/Q106 为 `/captureScene` 立的"flag 只管屏幕、不管捕获出口"这条口径只有共用同一条代码才立得住：将来新增一族辅助图层只改 `isEditorOnly()` 一处，截图自动跟着排除。**直接后果**是 `viewport.cameraFrustumAlways`/`viewport.lightMarkerAlways` 顶成 `true` 也截不进视锥线与灯球（§12.16 ③）。**② 取像素走离屏读回，不走 `canvas.toDataURL()` 直读 WebGL 画布** —— 直读要求建 context 时 `preserveDrawingBuffer: true`，而本渲染器没开，开了等于**给动画循环每一帧都多付一次全画布拷贝**，用一直存在的代价换一次按需动作，方向反了；离屏 `WebGLRenderTarget` + `readRenderTargetPixels` 是 §5.10 的 `/captureScene` 与 Details 预览**早就在跑**的通路，连**翻行**（GPU 第 0 行是画面底行）都写好了，本轮只是把相机从 `sensorCamera` 换成 `this.camera`、尺寸从传感器上限换成画布自己的 drawing buffer，所以除了 MSAA 没有新语义。产物**只进剪贴板**：`snapshotCanvas.toBlob()` ⇒ `navigator.clipboard.write([new ClipboardItem({"image/png": blob})])`，三类失败（无 `ClipboardItem`、非安全上下文、用户撤销权限）**一律 `showError` 报错，不做"改为下载一份"的降级** —— 降级会造出第二个用户可见行为与第二条判据，而"另存一份"本来就不是这句话要求的。
- **落点（四个新函数 + 一个字段组，全部在既有那条通路的旁边）**：`renderer.ts:captureViewport(canvas)` 是唯一对外入口（取 `getDrawingBufferSize()` 而不是 `getSize()`，见下条）→ `viewportPass(target, pixels)`（与 `sensorPass` 只差两处：相机换成视口相机、**什么都不替换** —— 背景、雾、材质都保持渲染循环留下的样子，因为截图要的就是屏幕那张图）→ `makeViewportTarget(width, height)`（`new THREE.WebGLRenderTarget(w, h, { samples: 4 })`，尺寸没变就复用；`isContextLost()` 时报错回 `null`）→ `viewportPixelBuffer(width, height)`；`main.ts` 新增 `snapshotCanvas`（**独立一块 2D 画布**，不与 `/captureScene` 的 `captureCanvas` 共用，因为两者尺寸不同、共用会让每次截图都把对方的画布撑成自己的尺寸）、`copyViewportSnapshot()`、工具栏 `<button data-action="snapshot" data-feature="viewport.snapshot">`、`else if (action === "snapshot") void copyViewportSnapshot()`；`features.json` 在 `viewport.frameScene` 之后插一键；`dispose()` 里跟着释放三个 viewport 缓存。
- **五个必须写在正文里的实现细节**：**① 尺寸取 `renderer.getDrawingBufferSize()` 而不是 `getSize()`** —— `resize()` 走的是 `setSize(w, h, false)`（不写 style），所以 `getSize()` 回的是 **CSS 尺寸**，在 `pixelRatio=2` 的屏上按它建目标只会截到画面的**左上四分之一**；headless 冒烟里 `devicePixelRatio=1`，两种写法都看不出差别，所以 §12.16 ① 的宽高判据钉的是 `#viewport` 的 `canvas.width/height`（drawing buffer）而不是 CSS 尺寸。**② `captureViewport()` 起手要 `orbit.update()` + `scene.updateMatrixWorld(true)`** —— 一次点击不经过渲染循环，orbit 相机的位置只在 `update()` 里从球坐标落回 `camera.position`，而 `Attach` 重挂一个节点之后到下一帧之前 `matrixWorld` 是旧的；不补这两下，截出来的就是**上一帧**的构图（§12.16 ⑤ 用 `frame()` 挪相机再截，正是为了钉这件事）。**③ viewport 的三个缓存字段自成一套**（`viewportTarget`/`viewportPixels`/`viewportImage`）—— 共用 sensor 那三个的话，窗口一改尺寸就会连带把 sensor 的 `ImageData` 缓存也作废，`/captureScene` 与 Details 预览白重建一遍。**④ 目标的 `texture.colorSpace` 必须显式设成 `SRGBColorSpace`**（**坑 82**）—— three 只对"画到屏幕"或"纹理色空间是 sRGB"的目标做输出编码，默认那张是**线性**的，于是读回来的字节全偏暗；本轮第一轮真机就被 §12.16 ② 的**下界**抓到（同一帧屏幕 `44110` 个亮像素、剪贴板只有 `3351`），而"描边/视锥两族为 `0`"这几条**照样全绿** —— 一张错误的图完全可以通过一张干净的图的全部判据。**⑤ 成功提示走 `showError` 那个唯一的 toast 出口**（`#toast`，5 秒），与 **Q77** 光照预设、**Q79** 本地位姿编辑同源 —— 那个函数名字叫 error，实际是应用**唯一**的用户可见通知面，本轮不为此新造第二个；也正因为它是共享出口，冒烟里连点几次截图必须**每次先等它清空**（**坑 84**）。
- **单测（`renderer.test.ts` 新增一个 `describe`，6 例；全量 383 → 389）**：现场是一台带网格的灯（`#4`）+ 一台只有 `Camera` 的物体（`#2`）+ 另一盏没选中的灯（`#5`），两个常驻 flag 都顶成 `true`、选中 `#4`，再手加 ghost / waypoint / `GridHelper` / `AxesHelper` 四族，凑出**十层**编辑层（视锥线、两盏球的其中一盏标签**故意让它本来就暗着**）。六例钉：① 渲染那一刻十层 `visible` 全 `false`、`render` 收到的正是 `(scene, this.camera)`、`orbit.update` 被调过、结束后**十层全恢复而那张暗着的标签仍然暗**（**坑 75** 的判据在截图这条路上重钉一遍）；② `render` 抛错时 `finally` 照样恢复、`setRenderTarget` 最后一次回到**进来时的旧值**、2D 画布**一个像素都没画**；③ 目标与读回缓冲的尺寸取 drawing buffer（`[96,40]` ⇒ `target.width/height` 与 `readRenderTargetPixels` 的参数都是 96×40）且 `target.samples > 0`；④ 翻行方向与 §5.10 一致（GPU 第 0 行落在画面**底行**）；⑤ 两次截图复用同一张 target、改 drawing buffer 才新建并丢掉 `ImageData`；⑥ 三种拒绝（尺寸为 0 / 已 `dispose` / context lost）都回 `false` 且**一个像素不画、scene graph 一字不动**。
