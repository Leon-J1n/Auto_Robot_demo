## 任务卡原文

### FEAT-2026-11-04-J —— 视口背景色可配置：`config/constant_config.json` 新增 `viewport_background_color`（**Q145**；口径与实装同一张卡；依赖 Q118、Q97、Q101）

- **起因（用户原话）**：「在 `config/constant_config.json` 中添加一个键，用于表示渲染窗口的背景色（默认是黑色），格式通常为 `#RRGGBB` 或 `#RGB`」。**这是一条纯前端的观感数值常量**，与 `shadows_enabled`（Q118）／`ghost_pose_opacity`（Q97）／`traj_waypoint_radius`（Q101）同族：浏览器读它决定清屏色，gateway 只是原样下发、从不渲染。用户已经把默认值（黑色）与格式（`#RRGGBB`/`#RGB`）说死。
- **为什么是常量、不是 `features.json` 键**：与 Q97/Q101/Q118 同一判据 —— `features.json` 每一项都是布尔、管"界面元素在不在"，而这条管的是"清成什么颜色"，是一个值不是开关；而且它没有 DOM 宿主（`parity_inventory.py` 指不出它管界面上的哪一块，§9.3 从头到尾的判据）。它进 `RuntimeConfig`（浏览器必须读；两份 `types.ts` 同步，**坑 6**），新增的是一个**可选**字段 `viewport_background_color?: string`，老 gateway 不下发时前端 fail-open 到黑色、不报错。
- **口径与实装同一轮**：`docs/Web前端需求规格v2.md` **§9.2** 的 sample json 添一行 `"viewport_background_color": "#000000"`（在 `shadows_enabled` 之后）并补一条常量说明（名字/日期/Q 号/类型/默认值/用户口径/为什么是常量不是 feature/进 `RuntimeConfig` 的理由/fail-open 判据/坑 22 重启），新增验收 **§12.39**（四层）与决议 **§13.58**；README 的 config 段（`shadows_enabled` 那句之后）就地补一句；`docs/UI优化记录表.md` 添一行；本文新增卡 **FEAT-2026-11-04-J** 与本行。历史留在本卡，正文不写"曾经如何"。
- **实装形态**：`config/constant_config.json` 新增 `"viewport_background_color": "#000000"`（在 `shadows_enabled` 之后）；`local_gateway.py:DEFAULT_CONSTANT_CONFIG` 同步新增同一条（**两处必须逐字一致** —— `test_gateway_routes.py:203` 把"出厂文件 == 内置默认"钉成一条测试，只改一处会让它红）；两份 `types.ts`（`types.ts` + `contracts/types.ts`）在 `RuntimeConfig` 的 `shadows_enabled?: boolean;` 之后加可选字段 `viewport_background_color?: string`（**坑 6** 逐字节相同）；`logic.ts` 新 `DEFAULT_VIEWPORT_BACKGROUND = "#000000"` 常量与 `viewportBackground(runtime)` fail-open 解析（只在收到 trim 之后匹配 `/^#(?:[0-9a-fA-F]{3}|[0-9a-fA-F]{6})$/` 的字符串时采用，否则一律回黑色 —— 与 `ghostOpacity()`/`shadowsEnabled()` 同构）；`renderer.ts` 新 `setBackgroundColor(color: string)`（只写 `scene.background = new THREE.Color(color)`，**不碰** `scene.fog`）；`main.ts:start()` 里接线 `renderer.setBackgroundColor(viewportBackground(config))`、import 添 `viewportBackground`。`world.ts`／`styles.css`／`placement.ts` **一字未动**，零新 feature 键、零新路由、零新动作。
- **本轮最重要的一处作用域判断：只改清屏色、不动距离雾**。`scene.fog` 仍是渲染器构造时的黑色（近 30/远 120）。用户口径只说"背景色"，而雾色影响的是远景衰减的观感、是另一件事；把两者合并会让这条键的承诺范围超出用户所说，也会让"调成浅色背景"意外地把远景一起洗掉。`renderer.test.ts` 那支负控制钉住这一点（设了 fog、调背景、断言 fog 原封不动）。**留给用户复核或改判**：若以后想让背景色一并带动雾色，是一条独立的口径（账记在 §13.58 ⑤）。**为什么在解析层校验、而不是把串直接丢给 `THREE.Color`**：`THREE.Color` 对认不出的串会静默回退，把校验放在 `logic.ts` 才能让"非法值 → 黑色"这条判据被单测钉住、也让 renderer 拿到的永远是一个已验证的串（Q96/Q105 那道"renderer 不读配置"的分工）。
