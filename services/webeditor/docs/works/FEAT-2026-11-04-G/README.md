## 任务卡原文

### FEAT-2026-11-04-G —— `LocalAxes` 新增 `offset` 字段：坐标轴原点可以离开物体局部原点（**Q142**；口径与实装同一张卡；依赖 Q130、Q132、Q119、Q105/Q106）

- **起因（用户原话，一句）**：「给LocalAxes组件添加一个新的参数offset:[x, y, z]，该参数表示用于绘制的坐标轴原点与模型原点的偏移量.如果缺省默认为[0,0,0]。完成任务后在本地创建提交并刷新场景规范等文档」。**这是给卡 ㊺（Q130）那层加一个字段，不是新能力**：`LocalAxes` 已经画出物体自己的三根轴，本轮只让"这三根轴从哪儿出发"可以由文件指定 —— 缺省仍是物体局部原点，所以既有场景文件与 OLS 资产一字不改照画。
- **字段口径**：`offset` 是 `[x, y, z]`（米），缺省 `[0, 0, 0]`；三根轴从**偏移后的原点**出发，**方向与长度不变**（`length` 仍管三根轴各自的长度，`offset` 只管它们共同的原点）；偏移随父链 `Transform.scale` 一起缩放、不做补偿，与 `length` 同族（被放大 2 倍的物体，其 `offset` 的 1 m 也是世界的 2 m）。**回退与告警按 §3 那套**：`offset` 不是 3 元素数组 → 告警 `LocalAxes offset <json> is not a 3-element array, using [0,0,0]`；任一分量不是有限数 → 告警 `LocalAxes offset[<i>] <json> is not a finite number, using [0,0,0]`；**键缺失不告警**（字段缺失按默认值回退、不是错误）。**一处判断：全有或全无** —— 一个分量坏了就把**整个** `offset` 落回 `[0,0,0]`（一条告警点名那个下标），而不是只坏那一轴；理由与 `length` 同族而**与 `colors` 相反**：`colors` 坏一个键只回那一轴的色（三色互不依赖），而一个"原点"是三个分量共同定义的一个点，只应用其中两个会得到一个不属于任何帧的原点。
- **口径与实装同一轮**：`docs/场景文件描述.md` §4.9 字段表添 `offset` 一行（含两种告警原话与"键缺失不告警"）；`docs/Web前端需求规格v2.md` §3 组件定义 `LocalAxes` 行添 `offset` 字段、添一句几何口径（"把整个帧从物体局部原点移开…随父链 `Transform.scale` 一起缩放，与 `length` 同族"）与一句回退口径，§12.26 ① 就地补 `offset` 判据（`world.test.ts` 与 `renderer.test.ts` 各一句）并把 `localAxesRig()` 的返回形状写成 `{length, colors, showLabels, offset, warnings}`；新增决议 **§13.56**；README 的编辑器图层那段就地补一句；`docs/UI优化记录表.md` 添一行；本文新增卡 ㊾ 与本行。**本卡这四件（卡体、§13.56、UI 表一行、README 一句）是补齐件**：offset 的代码与三处字段表更新由并行会话先落盘成 `851edf7`（见下"提交形态"），那一轮按本仓惯例还缺这四件，由本轮补上、**不替它编口径**（卡 ㊿ 的"一轮收尾"已如实记下这个缺口）。
- **实装形态**：`contracts/types.ts` 与 `types.ts` 各添 `offset?: Vec3`（`cmp types.ts contracts/types.ts` 逐字节相同，**坑 6**）；`logic.ts:LocalAxesRig` 添 `offset: Vec3`，`localAxesRig()` 在 `showLabels` 与 `warnings` 之间解析并返回它（缺省 `[0,0,0]`、坏形状/坏分量按上面那两条告警后落回 `[0,0,0]`）—— **解析端拿它的 `warnings`、渲染端拿它的数值，同一份回退不可能两头各算一套**（与 Q130 立 `localAxesRig()` 的理由同一条）；`renderer.ts:addLocalAxes()` 在打好 `userData` 那几面标志之后、画三根轴之前，一句 `group.position.set(rig.offset[0], rig.offset[1], rig.offset[2])`。**为什么落在 Group 的 `position` 而不是逐顶点**：三根轴与（`show_labels` 为真时的）三枚标签 Sprite 都挂在这一个 Group 之下、各自从 Group 原点出发，所以**移开 Group 一处，轴与标签一起走**，不需要每帧重算、也不需要动任何一条几何（与 §4.9"没有任何一处每帧重算"那条口径一致）。`world.ts`／`main.ts`／`placement.ts`／`styles.css` 一字未动（`offset` 随 `properties` 整份进 `rawComponents`，§3.8 那条既有通路免费保留它），零新键、零新路由、零新动作。
- **它是编辑层，所以这一轮五条对外通道一个字节不变**：`userData.localAxes` 那面身份标志一字未动，`isEditorOnly()`／`hideOverlays()`／`expandGeometry()`／`selectable()` 四处判据原样 ⇒ `/captureScene`（§5.10）、视口截图（**Q108**）、`worldAabb()`、`/get2DAABB`（§5.11）与拾取五条通道**都不因 `offset` 改变**（轴仍不是 `Mesh`、仍不在 `pick()` 的射线集合里，偏移只是把它们画在别处）。`renderer.test.ts` 里 Q130 那条 "keeps the layer out of the extent, the capture and the click list" 原样通过 —— `offset` 的默认 `[0,0,0]` 让 Group 仍在原点，所有既有断言不动。
- **单测（597 → 601 例 / 18 文件，+4）**：`logic.test.ts` +2（`localAxesRig({offset:[0.1,-0.2,0.3]}).offset` 按写的走、缺省与 `undefined` 都落 `[0,0,0]`；坏形状四种 —— 字符串、2 元素数组、`NaN` 分量、字符串分量 —— 各告警并按 `[0,0,0]`，且 `localAxesRig({}).warnings` 为空）、`renderer.test.ts` +1（`group.position.toArray()` 等于 `offset`、三根轴顶点仍等于 `length`、`show_labels` 为真时三枚标签仍在轴末端 ⇒ 移开的是整个帧）、`world.test.ts` +1（坏 `offset` 走该物体自己的 `[world] object N:` 告警通路）。**负控制**：撤掉 `renderer.ts` 那句 `group.position.set` ⇒ `renderer.test.ts` 那支立刻红；把 `logic.ts` 的"全有或全无"改成"只坏那一轴"⇒ `logic.test.ts` 坏分量那支红。
