假设此时OLS,Qwen,AgentBrain,Web-gateway服务已启动。

1.浏览器访问http://127.0.0.1:8099,此时应该为空场景，Agent服务可达性为联通

2.浏览器在页面打开后自动与gateway绑定浏览器ID

3.浏览器从资产库选择某个场景（或手动从Load Scene按钮上传一个场景），浏览器此时正常显示场景，可以切换光照预设等

4.在Agent面板中输入命令，浏览器传递此时场景和命令给gateway，gateway收到后创建一个会话，然后浏览器锁定资产库面板不允许再从资产库面板切换场景。此时，对话历史中应当有只有一个历史（当前会话）。

5.gateway向AgentBrain服务发送相关请求，创建任务。

6.AgentBrain开始处理任务，首先发送锁定请求（浏览器在场景锁定时不能切换灯光），然后AgentBrain向gateway发送相关请求获取必要数据（如captureScene）。

7.AgentBrain处理中，得到新的场景，并向gateway提交该场景。gateway将新场景保存，并通知给浏览器，浏览器刷新场景。

8.AgentBrain处理完成，得到任务分解，向gateway发送解锁请求。AgentBrain将任务标记为已完成。gateway会在适当时间调用相关接口查询任务状态。

9.在同一会话中，浏览器继续输入命令，并发送。由于会话已经创建，gateway无需重新创建对话。

10.gateway向AgentBrain服务发送相关请求，创建任务。

11.AgentBrain开始处理新任务，首先发送锁定请求，然后AgentBrain向gateway发送相关请求获取必要数据（如captureScene）。

12.用户点击资产库面板，尝试切换场景，提示：会话正在进行中，无法切换场景，需要新建会话。是/否

13.点击是，浏览器向gateway请求创建一个新会话。并切换到新场景。此时，对话历史中应当有2个历史（其中一个是上一轮正在运行中的）。

14.由于当前在新会话中还未给AgentBrain发送命令，所有我们依然能在资产库面板中切换场景或手动上传场景。

15.发送新命令，gateway向AgentBrain服务发送相关请求，创建任务。后续处理流程同6-8。

16.点击新建对话按钮，浏览器向gateway请求创建一个新会话。浏览器切换到一个空场景。此时，对话历史中应当有3个历史。

17.不上传也不选择一个场景，直接在空场景中发送命令。建议发送“增加一个苹果”（或“抓起苹果”）以避免资产库中两个篮子模型造成歧义；gateway向AgentBrain服务发送相关请求，创建任务。

18.AgentBrain首先请求锁定。然后AgentBrain会根据要求自己生成一个场景（“增加一个苹果”已验证可用；“把苹果放进盒子里”会因 basket 在 OLS 中有蓝色/白色两个模型而返回 asset_ambiguous，不作为空场景验收命令），然后向gateway提交该场景。gateway将新场景保存，并通知给浏览器，浏览器刷新场景。

19.AgentBrain处理完成，得到任务分解，向gateway发送解锁。AgentBrain将任务标记为已完成。gateway会在适当时间调用相关接口查询任务状态。

20.切换回第一个会话，此时我们应当能看到该会话中的任务已完成（虽然我们切换了会话和场景，但Agent依然完成了相关工作）。

21.刷新浏览器页面，重新加载后依然在第一个会话，且对话历史（包括过往发送的命令和Agent回复）依然存在。

22.切换到第二个会话，然后关闭浏览器。然后重新打开http://127.0.0.1:8099。重新加载后，依然在第二个会话，且对话历史依然存在。

补充：Agent 任务的终态回复由 Gateway 在任务所属会话中按 `job.id` 持久化，并按 `role + turnId` 去重。因此任务在浏览器关闭期间完成时，重开页面仍应看到原会话的 Agent 回复；旧页面重连后重复回传同一回复也不应产生重复气泡。

23.切换到第三个会话，发送新的命令。然后迅速关闭浏览器。等待一段时间后重新打开http://127.0.0.1:8099，此时任务状态应该为失败（因为Agent无法通过浏览器获取必要信息，如捕捉场景等）

24.在第三个会话再发送一条命令，然后等待一小段时间，但要在Agent任务完成前关闭浏览器。等待一段时间后重新打开http://127.0.0.1:8099。此时任务状态应该为成功（或仍在进行中，如果等的时间不够久的话），因为AgentBrain在浏览器关闭前就已经拿到了需要的信息。如果AgentBrain在浏览器关闭时提交了新的世界，重新加载后浏览器也应该显示最新的世界。

25.关闭浏览器。

26.关闭gateway服务，然后重启gateway。

27.打开http://127.0.0.1:8099，此时场景应当为空，没有存在的会话。





参考命令有：把苹果放进盒子里，把苹果放到糖盒右边，把香蕉放进盒子里 等。

注意：在全流程中，不应出现Agent服务状态（降级）。Agent服务应当是就绪状态。

- 前端提交任务时会带上当时选中的 `conversationId`；Gateway 将任务回复写入该历史行，避免同一 Brain session 存在多条历史时误写到较早的记录。恢复任务状态的响应只更新仍处于前台的会话。
- 普通 `/updateWorld` 编辑沿用当前 `scene_version + 1`；严格 `/commitWorld` 应用 Brain 的候选版本，不再额外递增。

- 新建会话或首次绑定期间，显式 `/sessions`、场景 `state_sync` 自动绑定、`/api/sessionState` 恢复和历史会话激活可能交错；Gateway 必须协调这些转换并丢弃过期响应。新任务发送前，选中历史行的 `sessionID` 必须与 Gateway 当前 session 一致；首次加载、加载场景后立即发送以及新建空场景后立即发送都应按此条件验证。

### 会话场景相机绑定回归补充

- 显式新建会话后，浏览器可能先上报创建会话前仍显示的旧场景；Gateway 会暂缓该基线报告，直到收到用户选择的场景，再更新当前历史行和该会话快照。
- 新对话请求切换到与当前场景不同的预期场景（例如空场景）时，Gateway 不会把旧场景的相机绑定到新 session。若后续场景报告出现相机候选，而当前 session 没有绑定相机，或所绑定相机不在候选清单中，Gateway 会自动创建一个绑定可用相机的新 Agent session；目标场景没有候选时保留无相机会话。
- 自动重绑定请求失败时保留重绑定状态；下一次场景同步会重试。新历史行创建前，无论重绑定连续失败还是成功返回，都不会把新会话/场景写回旧历史行；新行创建后再绑定最终 session 和场景。
- 历史激活与新建会话都按历史行 ID 保护旧记录；即使 AgentBrain 复用相同 sessionID，或场景状态在历史行激活前到达，也不会改写旧行。
