- **起因（用户原话）**：「我发现了一个新bug：相机悬浮窗在相机数目比较多的时候可能会超长。我希望当数目较多时显示一个滚动条。修复完成后在本地创建git提交」。这是一处**纯 CSS 布局缺陷**，落在 Q138/Q139 建起来的那扇窗上（§4.8.9）。
- **病根（对着真实样式表量过，不凭猜）**：`.camera-wall-cells` **本来就带** `overflow:auto` + `min-height:0`，`.camera-wall` **本来就带** `max-height:calc(100% - 20rem)` —— 三样齐全却照样超长。原因是 `max-height` 只夹**窗自己那个盒**，而 grid 的**隐式 `auto` 行**按 max-content 取高、不受 `max-height` 回压：相机一多，格子那一行照常长到内容那么高、从窗盒底边**溢出去**，被外层 `.canvas-wrap` 的 `overflow:hidden` 裁掉；与此同时 `.camera-wall-cells` 这个元素**自己没有溢出**（它的高 == 它的内容高，`scrollHeight === clientHeight`），所以它那条 `overflow:auto` **永远不触发**。用户看到的"超长 + 没有滚动条"正是这两件事的合成。
- **修法（一行 CSS）**：给 `.camera-wall` 补 `grid-template-rows:auto minmax(0,1fr)` —— 标题栏那一行 `auto`、格子那一行 `minmax(0,1fr)`。**为什么这样就够**：`minmax(0,1fr)` 里那个 `0` 抹掉了 `auto` 行"最小也要 max-content"的下限，`1fr` 让这一行只吃**窗被 `max-height` 夹住之后余下的空间** ⇒ 格子那一行变得比内容矮、`.camera-wall-cells` 自己终于溢出、那条既有的 `overflow:auto` 才真的滚起来。**修在窗上、不修在格子上**：滚动的是格子那一行，但能让它被夹住的约束只能加在定义行的父级；给 `.camera-wall-cells` 自己再套一个 `max-height` 要减掉标题栏高 + gap + padding（都是动值），脆。**为什么不改成 flex、也不把 `max-height` 换成 `height`**：flex 列实测同样能滚，但那是对这扇窗既有 grid 布局的更大改写，一行 `grid-template-rows` 就够；`height` 会让窗**永远撑到上限**、一台相机时也占满视口高度，那正是要守住的紧凑态的反面。
