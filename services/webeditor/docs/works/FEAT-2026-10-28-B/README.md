## 任务卡原文

### FEAT-2026-10-28-B —— 视口的两件家具：`viewport.worldAxes` 与 `viewport.grid`（**Q131**；口径与实装同一张卡；依赖 M1-4、Q96、Q105/Q106、Q118、Q130）

- **起因（用户原话）**：「在features.json中新增两个键，用于控制渲染窗口中是否显示世界原点坐标轴和是否显示网格」。四个决定记在需求规格 §13.44 的 Q131 行：**两个键而不是一个"显示辅助图层"**（网格是"场有多大"的尺、三根轴是"哪边是 +X/+Y/+Z"的尺，关一个的动机不会关另一个）、**默认都 `true`**、**fail-closed 下明知不重启 gateway 会让它们消失仍不补常量**（与 **Q118** 相反，理由写在下面那条）、**判据重心从"画不画得进图"挪到"谁写 `visible`"**。
- **口径与实装同一轮**：`docs/Web前端需求规格v2.md` §4.4 新增本节一条（两件家具什么时候出现在屏幕上，并与 §4.9 那族轴划清界限）、§9.3 新增那两条键（85 → **87 键**）、验收新增 **§12.27**（①单测／②负控制／③真浏览器／④接口面与回归 四层）、决议新增 **§13.44**；`docs/场景文件描述.md` §4.9 末补一段对照（视口那三根世界轴与网格**不归场景文件管**，免得把两族轴读成同一族）。
- **实装形态**：`editor/src/renderer.ts` 把构造里原来那两行（局部 `const grid = new THREE.GridHelper(80, 80, …)` 与 `this.scene.add(new THREE.AxesHelper(1.5))`）提成两个 `readonly` 字段 `gridHelper`/`axesHelper`，配 `gridEnabled`/`worldAxesEnabled` 两个布尔，**构造时按同名布尔起一次 `visible`**（不变式：字段是真相、`visible` 是它的投影）；新增 `setGridEnabled()`/`setWorldAxesEnabled()` 各写自己那一件；`applyOverlayVisibility()` 末尾那行 `console.debug("Viewport markers …")` 抽成 `logOverlayState()` 单点输出、两个 setter 也走它并各添一个读数。`editor/src/main.ts` 只做两次单键直读把布尔推给 setter，渲染器对配置一无所知（Q96/Q105/Q106/Q130 一贯的分工）。
- **为什么这条的判据不是"键能关掉画面"**：两件东西的 `type` 都以 `Helper` 结尾 ⇒ `isEditorOnly()` 从 M1-4 起就把它们按在采集、视口截图（**Q108**）、录制默认态（**Q121**）与所有量测之外，所以**键开键关 `/captureScene` 与 `worldAabb()` 一个字节都不变** —— 那是既有排除的推论，本轮新写它等于测一件本来就成立的事。本轮唯一可能出错的新东西是**第二个写者**：两个 helper 挂在 `scene` 之下，而 `applyOverlayVisibility()` 只走 `markerNodes()`（那只遍历物体节点的子节点），**结构上碰不到它们** ⇒ setter 是唯一写者，一次 `select()` 不会替一个关掉的键把层点亮（**Q105/Q106** 那族"选中才亮"的规则在这里不适用，与卡 ㊲ 的 `LocalAxes` 同一个口径）；反过来把它们搬进那一趟遍历要先撑破 `markerStates()` 的 `{objectId, kind, visible}` 形状（它们没有 `objectId`），换来的只有"多一处写它们的代码"。
- **两处与既有决议相反、按理由保留**：**① 默认 `true`** —— 本轮之前这两件家具每个人都在看，`false` 等于在没人要求的情况下撤走既有画面。**② 不补常量** —— `featureEnabled` fail-closed 且 gateway 的 `features.json` 是启动时快照（**坑 22**）⇒ **不重启 gateway，这两枚新键在旧进程里读成 `false`，屏幕上原本一直看得见的网格与坐标轴会消失**，这是本表里少数"缺席有代价"的键之一，形状与 **Q118** 当年一模一样；差别在 Q118 要保的是一份**构建方的决定**（默认投不投影，且撤掉的东西落在采集与画面上都看得见），本条撤掉的只是屏幕上的参考线、症状一眼对上一条运维动作（重启），而补常量要多写一份 `config/constant_config.json` 内置默认 + 两份 `types.ts` 的 `RuntimeConfig` + 一次重启语义（**坑 6**），收益为零 —— 于是把"改值要重启"写死在 §9.3 与 §12.27 ② 的键旁边，而不是给它兜底。**没有 DOM 宿主、也不配工具栏勾选框**（用户要的是配置里的两个键；有宿主的键是 §4.8.5/§4.8.6 那两条的形状）。
- **单测（523 → 528 例 / 17 文件，+5，全在 `renderer.test.ts` 新 `describe("viewport furniture: grid and world axes (规格 §4.4, Q131)")`）**：A 各自管各自的（关网格 ⇒ 轴仍 `true`，反之亦然，再开回原样）；B 选中态不得越权（先关两层再 `select(2)`/`select(null)`，那一族视锥线照它的规则亮、两层**继续 `false`** —— 本节唯一那条"谁写 `visible`"判据）；C 从屏幕上按掉不是从场景里摘走（`scene.children` 仍含两者）；D 本来就是编辑层（`isEditorOnly()` 对两者回 `true`、`hideOverlays()` 把可见的两者列进按掉的一层，**并且键先关掉的那一层不会被采集"恢复"成可见** —— **坑 75** 落在两件家具上）；E 可读（`Viewport markers` 那行 JSON 里 `gridEnabled`/`worldAxesEnabled` 随 setter 变，`console.debug` 用 spy 读、结尾 `mockRestore`）。夹具 `adapterFixture()` 把两件 helper 造在 `scene` 之外（`gridHelper`/`axesHelper`/两个布尔一起 `Object.assign` 进原型壳），**不测构造**、只测两个键与两条通路；C/D 两支自己 `scene.add(...)` 一次，因为它们要问的是采集那一趟遍历。
