## 任务卡原文

### FEAT-2026-10-27-C —— UI 优化第四轮：界面只说当前状态 + 任务进行中「新建会话」不再被浏览器替它拒绝（Q127/Q128；新卡 ㉟；依赖 FEAT-2026-10-27-B、FEAT-2026-10-26-A）

- **起因（用户原话）**：「任务进行中，点击新建会话有时会显示"任务#xx持有租约，新建会话不会把它放下来"，并且创建失败；把带"租约"或类似字样的描述改成最直白的当前状态陈述（如：任务进行中，新建会话失败）」。一条诉求，两层毛病：文案是用户看得见的部分，**"并且创建失败"那半句是浏览器自己造的**。
- **Q127 文案侧（五句 + 弹窗两行）**：`任务 #N 进行中，新建会话失败`（门未带 `allowActiveTask` 时）、`上一个任务的结果还没确认，新建会话失败`（quarantine）、`还没读到会话状态，新建会话失败`（权威路由未答）、`任务 #N 进行中，光照和阴影暂时改不了，任务结束后自动恢复`（灯光／阴影共用一句，把两个控件的名字都写进去，不为它加一个"控件名"参数）、弹窗第一行 `任务进行中，场景暂时不能改。` 与 `这个会话里有任务正在进行。`。**被撤下的是协议名词而不是机制**：`租约`／`接管`／`现场`／`冻结`／`§9`／`GET /api/sessionState`／`POST /resolveUncertain` 从界面文本里清零，规则本身一字未改（§4.6、§4.8.1、§9 正文照旧），与 **Q124** 是同一条规则的两次应用。**Gateway／Brain 的原话不改**（§4 第 2 层），`task_busy` 仍照原文念。
- **Q128 那道门的假失败（本轮唯一真 bug）**：`createSession(allowActiveTask, resetWorld)` 第一句无条件 `sessionDoor()`，门里 `view.lease !== null` 就 return —— 而两枚显式入口传的都是 `true`（`acceptPhaseBlock` 的 `createSession(true)`、`createConversation` 的 `createSession(true, true)`），网关判据是 `held == "lease" and not allow_active_task`（`local_gateway.py`，带 flag 时把租约搬进旧会话上下文让任务照旧跑完，`tests/test_gateway_sessions.py:297` 钉的就是这条）。⇒ 浏览器在发出请求**之前**替网关拒绝，`allowActiveTask` 成了死参数，「新建会话」在任务运行期**必红**；弹窗尤其荒谬：`#phase-block` 只在 `agent_owned` 出现，而运行期常态带着租约，等于它问"要不要新建会话？"、用户答应后答"不行"。**修法只放开这一支**：`newSessionView(view, nameOf, allowActiveTask)` 的第三参数由 `sessionDoor(allowActiveTask)` 传入，为真时不因 `lease` 拒绝；**quarantine 两侧照旧拦**（§8.3 新建会话不是解锁证据），`commit_unconfirmed` 由网关拦（`SceneLeaseView` 不含该字段 ⇒ 浏览器不凭缺字段放行）。**不撤销的东西**：租约不释放、任务不取消、请求形状不变。
- **单测（492 → 497 例 / 17 文件，+5）**：`session_state.test.ts` 三支新的（`allowActiveTask` 开门正控制、quarantine 带 flag 仍拒、`Q127` 那组"四句界面文本 × 七个内部词"否定式 + 一支"四句都还在"防漏）并把 `lightingFreeze`／三句 `blocked` 由 `toContain` 升级为 `toBe` 整句钉死；`local_edits.test.ts` 一支新的（两个常量的内部词否定式）并把 `PHASE_BLOCK_MESSAGE` 由 `toContain("Agent 接管")` 改判整句。**为什么这轮有单测面而上一轮没有**：本轮改的是 `session_state.ts`／`local_edits.ts` 两个**纯函数模块**的返回值，`main.ts` 的时序仍然没有单测面。
