## 任务卡原文

### FEAT-2026-10-19-B —— 轨迹路点球：叶子机械臂末端的一串小球（Q101）+ 从 URDF 推末端 link（Q102）+ 工具栏「显示所有轨迹路点」（新卡 ㉓；依赖 M2-1、M4-1、M4-3、M4-4、FEAT-2026-10-17-B、FEAT-2026-10-19-A）

- **起因（用户原话）**：「添加一个新功能：进入播放模式时显示机械臂轨迹路点，即每条轨迹中机械臂末端的位置。需要显示位置的机械臂为每个机械臂连接链上的叶子机械臂（假设有两个物体带有 RobotDriver，其中一个作为父机械臂，另一个通过 RobotAttach 组件连接到父机械臂，那么只需要显示子机械臂在这个轨迹中的每个末端位置）。只需要在世界中用若干指定颜色的小球作为路点的表示。此外，在工具栏中提供一个勾选框"显示所有轨迹路点"。当勾选框未勾选时，只显示当前轨迹的路点。否则，用不同颜色显示所有轨迹的路点。考虑到轨迹可能会比较密，你需要在配置中添加两个参数：1.路点小球半径 2.每 N 帧选取一个路点进行展示」。四个关键取舍用提问钉死，用户选定：**① 末端取点 = 「抓取中心（Q89 的挂载 offset）」**（落地为"从 URDF 结构推"，见下第 3 条与 **Q102**，语义与抓取中心同一点而判据换了）；**② 默认值 = 半径 0.02 m、每 10 帧一个**；**③ 配色 = 代码内置固定调色板**；**④ 重算时机 = 载入/切换轨迹时算，世界改动后再算**。同日追加一句硬口径：「轨迹路点，需要根据机械臂的urdf文件确定末端link，再确定路点位置。注意：game标签里面是其他场景用到的」—— 前半句把取点从"前端自己认的一个 link 名"升级为"从模型结构推导"；后半句是**排除条款**，但**全仓与 OLS 全部 URDF 资产里没有任何 `<game>` 标签**（grep 无命中），最接近的是仿真/耦合类标签（`<gazebo>`、`<mimic>`、`<transmission>`），故按"只有 `<link>`/`<joint>` 参与结构判定"落地，并把这条**作为待用户确认的假设**记进 **§13.29（Q102）**。决议记 **§13.29（Q101、Q102）**，正文就地修订 **§7.1**（勾选框那条 DOM 与四条口径）、**§7.3**（新增"轨迹路点球"七条）、**§8.6**（父链成环改为忽略，见第 9 条）、**§9.2**（两个新常量）、**§9.3**（新键那一段）、**§12.13**（新增验收项）。**`features.json` 81 → 82 键**（新增 `playback.trajWaypoints`），`docs/feature-inventory.csv`、`docs/api-inventory.json`、`docs/parity-probes.json` 随之重生成（探针里只有 `runtimeConfig` 那条从 `keys:14 / features:81` 变成 `16 / 82`）。
- **画谁 = 连接链上的叶子机械臂**：判据收成一个纯函数 `logic.ts:leafArmIds(objectIds, parentOf)` —— 候选是**这条 clip 携带的、且在世界里带 `RobotDriver` 的物体**（与 §7.3 幽灵第 7 条同一套 `Traj.objects` 遍历），对每台驱动器物体沿父链往上走，途中再碰到另一台驱动器物体就说明它是**祖先**、把它剔掉；`parentOf` 由调用方给，`main.ts:leafArmTargets()` 递的是**世界文件声明的挂载关系**（`attachmentMount.objectId` 优先，没有 `RobotAttachment` 时退回 `Transform.parent`，两者对已接受的挂载一致，因为 `world.ts:applyAttachment` 会对齐）。于是真实场景 3（`2=UR5eArm` 为父、`3=Robotiq2F85Gripper` 挂在它 `wrist_3_link`）只有夹爪有一层球，父臂不画；链更长（A←B←C）只剩 C；场上只有一台驱动器物体时它自己就是叶子、照画。父链**成环**时这个走查会走出去而不是转圈（用例 `walks back out of a cycle instead of spinning`）。
- **点取在哪 = 该臂 URDF 里最深的叶 link 的世界位置均值**（**Q102**）：`urdf.ts:toolTipLinks(robot)` 在**解析后的 `UrdfRobot` 图**上取"不作为任何关节的 parent"的 link 集合、只留距根最深那一层（读 `<link>`/`<joint>`，含 fixed joint；`<gazebo>`/`<mimic>`/`<transmission>` 不参与）。真实资产逐台实测（OLS `data/robots/*/urdf/*.urdf`）：每台**臂**恰有一个最深叶 link（robot 1 `attachment_site`、robot 5/6 `tool0`、robot 7 `Link6`、robot 8 `link6`、robot 9 `link7`、robot 12 `link_tcp`），均值就是它自己；每台**夹爪**的最深叶恰是**左右对称的两块指垫**（robot 2 `robotiq_2f85_right/left_silicone_pad`、robot 10 `right/left_inner_finger_pad`、robot 13 两个 `*_finger_tip_frame`、robot 14 `gripper_right/left_silicone_pad`），对称两点均值**必在对称面上** —— 那正是夹取发生的地方，与 **Q89** 给挂载 offset 的论证同构，只是这次从模型里读出来而不是文件里写死。取位置的是 `renderer.ts:toolTipPosition(objectId)`：读**已展开的 `UrdfTree` 节点**世界位置（所以跟着臂的 base 走），再乘 `simWorld.matrixWorld` 的逆把 Z-up 那次旋转退回来，落回世界文件自己的坐标系。**与 §8.6 的挂载点是两条路且不改它**：Attach 重挂父仍走 `endEffectorNode()`（`joint_sequence` 末条关节的 child），因为 Q89 的苹果携带段位姿 `(0, -0.017507, 0.101727)` 就是按那一帧点写的，换判据等于把已发布 clip 的抓取动作改歪；而 driver 原点在几何上偏在一根手指里，拿它当路点会跟着手指走。
- **两个参数进 §9.2 常量，不进 `features.json`**：`traj_waypoint_radius`（世界米，默认 `0.02`）与 `traj_waypoint_stride_frames`（默认 `10`）。三处同步：`config/constant_config.json`、`local_gateway.py:DEFAULT_CONSTANT_CONFIG`（回归用例 `tests/test_gateway_routes.py` 钉住两份相等）、两份逐字节相同的 `types.ts`/`contracts/types.ts` 的 `RuntimeConfig`（**坑 6**）。它们与 `ghost_pose_opacity` 同族（纯前端画法、没有服务端消费者 ⇒ 进 `RuntimeConfig` 而不是 agent 三件套那类网关自用项；`features.json` 每项都是布尔，这两项是数值）。回落口径 `logic.ts:waypointSettings(runtime)` 与 `ghostOpacity()` **完全同构**（fail-open）：半径只在**有限正浮点**时采用、stride 只在**有限正整数**时采用，缺字段/`null`/字符串/`0`/负数/`NaN` 一律回默认 —— 半径 0 等于把东西缩没、stride 0 会把采样循环卡死，两者都不是"用户想要的值"。取帧 `waypointFrames(total, stride)` 是 `0, N, 2N, …` **再加末帧**（末帧已在等差数列上就不重复），实测 720 帧 ⇒ **73** 个、840 帧 ⇒ **85** 个、840 帧配 stride 20 ⇒ **43** 个。和浓淡常量一样**读的是构建时刻**（**坑 22**）：改值要重载 clip 且重启 gateway。
- **扫描是"一次性"的，触发只有两处**：`main.ts:recomputeWaypoints()` 对**这一批的每一条** clip 各建一个 `TrajFrameProvider`，按上面的帧序列逐个 `provider.frame(f)`（同一套 §8.4 FK 与 §8.6 重挂父），每次读一次叶子臂的末端位置，扫完把这条 clip 的 Attach 事件按 §8.6 `driver.restoreParent(childId)` 放回世界文件声明的层级，最后 `showFrame(state.playIndex)` 把播放头放回原处 —— 用户看不到中间态、播放位置也不变。**①批次落定**（`updateTraj` 到达、下拉框切换、本地 Load Traj）走 `setTrajectory()` ⇒ 全量重扫 + 缓存 `waypointCache: Map<trajIndex, {objectId, points}[]>`；**②某条臂的 URDF 晚于 clip 落地**走新加的 `scheduleRobotLanding()`（第 8 条）。此后的勾选框两态、点选轨迹**只改可见性**（`setWaypointVisibility`），一次都不重扫。写入退出播放（**Q76**）与手动 Load Scene 都过 `setTrajectory(null)` ⇒ 顺手清空缓存并逐层 dispose，所以"世界改动之后再算"不需要挂任何写入钩子：**任何调用方写入都会结束播放，而播放结束路点就没了**。
- **渲染侧：每 (clip, 叶子臂) 一层 `InstancedMesh`**（`renderer.ts`）。`key = "<轨迹下标>:<物体 id>"`（一条 clip 可以带两台互不相连的臂 ⇒ 一条 key 只能定一台）。四个入口 —— `setWaypointPaths(paths, radius)` 建/复用/重建并逐点写实例矩阵、`setWaypointVisibility(keys)` 只管两态显隐、`clearWaypoints()` 逐层移除、`waypointLayers()` 把当前层读回来给诊断行。一份几何 + 一份材质被整层共用（半径与颜色描述的是层不是点），所以**半径、颜色或容量任一项变了就整层换掉**，复用条件是三项都对得上；换层时旧的必须同时离开舞台和 map，否则改一次半径会在舞台上叠出两串球。颜色 `logic.ts:WAYPOINT_COLORS` 六个色按**轨迹下标**循环（`waypointColor(index)`），不进常量配置 —— 配色要的是"两条轨迹一眼分开"，交给配置只会被人配成两个相近的蓝；跟着轨迹下标而不是"当前可见集合"走，所以同一条轨迹勾选/取消时**不变色**。诊断行 `console.debug("Trajectory waypoints " + JSON.stringify({active, showAll, layers}))` 是本轮唯一的取证出口（§12.13），`waypointLayers()` 里逐点从实例矩阵读回 `[e[12],e[13],e[14]` 平移分量]，因为 ⑥⑦ 比的是坐标而不是球数；它只在批次、勾选、清空三处调用，不在每帧路径上。
- **它是编辑层，不进任何对外通道**（与幽灵/gizmo/包围盒同一判据，§4.4）：层挂在 `simWorld` 之下（吃同一个 Z-up 换算）但**不进** `nodes`/`robotTrees` ⇒ 层级树、`#panel-count`、Details、拾取射线、`worldAabb()`（`/get2DAABB`、`frame()`）、`World.toJSON()`/`/getWorld` 全看不见它；`isEditorOnly()` 新增一条 `object.userData.waypoint === true`，`hideOverlays()` 把它连同幽灵一起挡在 `/captureScene` 与相机预览之外；`disposeScene()` 里补 `clearWaypoints()`。勾选状态存 `state.waypoints.showAll`，**不进 wire、不回传**，页面重载回到未勾选。
- **本轮真正的技术发现（坑 67）：一条臂的 URDF 晚于 clip 到达，路点永远画不出来，而且机械臂会停在场景文件声明的那一帧**。真机现场第一次跑 §12.13 时诊断行恒为 `layers: []` —— 冒烟里 `scene3()` 拿 `/get2DAABB` 的 **200** 当"机器人已就位"的闸门，而 200 只说明该物体有可测几何、**不说明 URDF 已展开**（未展开时父物体与子物体量出**同一个盒子**），于是扫描时 `toolTipPosition()` 一律 `null`。修法两半：① `renderer.ts:loadModel()` 展开完一棵关节树就报 `onRobotTree(objectId)`，`main.ts:scheduleRobotLanding()` 把同一 tick 里落地的多台并成一次「`showFrame(state.playIndex)` + `recomputeWaypoints()`」；② 冒烟侧的判据换成与开关无关的 `waitStageSettled()`（父/子盒子**不再相同**且**连续两次读数一致**）。**②里照出一条与路点无关的老 bug**：`buildRobot()` 一律 `applyDeclaredJointPositions()`，所以臂的 URDF 只要晚于 clip 落地，那台臂就停在**声明位**而不是播放帧上 —— 时间条还写着 `700 / 839`，画面里的臂却回了零位；把 `playback.trajWaypoints` 关掉仍然复现 ⇒ 与新功能无关（**坑 62** 的判据），所以这条重放**不受 feature 门控**。取证（`Temp\scene5probe\wp_sensor.cjs`，逐 0.5 s 打印父/子盒中心）：修前 `OFF t=0.0s {"2":[0,0.18,0.51],"3":[0,0.18,0.51]}`（同一个盒子）⇒ 修后 `OFF t=1.0s {"2":[-0.19,0.16,0.83],"3":[-0.35,0.33,0.71]}`，与 ON 那一路**逐位相同**，两张 `/captureScene` 的 PNG 与 depth **逐字节相同**、浏览器侧像素差 **0 个**。三条口径写进坑 67：凡"从活场景图里量几何位置"的功能都要有一条**资产晚到**的自愈路径；闸门要量"被量的那个东西存在"而不是"某个 200"；两态像素对比两边必须过同一道与开关无关的闸门。
