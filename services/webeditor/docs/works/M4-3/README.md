## 任务卡原文

#### M4-3 关节驱动与前向运动学（**最大工作量项**）
- **规格**：§8.3、§8.4、§1.1 职责表
- **涉及**：`urdf.ts`（可动化）、`renderer.ts`（新增 `applyJointValues`）、`world.ts`(`RobotDriver` 读取)
- **改动要点**：机器人判定改为"有 `RobotDriver` 组件"（不再用 `scene.robot.id`）；前 6 分量按 `joint_sequence` 顺序写关节（弧度），按 `joint_limits` 裁剪（超界**只告警一次**）；第 7 分量（夹爪）**只记录不驱动几何**（O1 待定，禁止猜关节名）；非机器人物体按 `x,y,z + qx,qy,qz,qw` 相对父物体赋值；每帧 `updateMatrixWorld`。
- **DoD**：把 fixture 轨迹设为第 0 帧与第 340 帧，机械臂 link 世界坐标发生变化且苹果随 TCP 移动（`traj.test.ts` 或 `renderer.test.ts` 数值断言）。
- **验证**：`npx vitest run editor/src`。
- **已完成（2026-10-09）**：卡片原写的落点（`renderer.ts` 新增 `applyJointValues`、测试写进 `traj.test.ts`/`renderer.test.ts`）改为**新模块 `editor/src/drivers.ts:TrajDriver` + 新增 `drivers.test.ts`**，理由与 view 边界见 §13.8 **Q39**；`urdf.ts` 补 `setJointValue`（§8.4 的可动化入口，值复合在 joint origin 之上、绝不覆盖 origin）与 `endEffectorNode`（§8.6 的 TCP 推导，**Q38**）；`traj.ts` 补 `poseAtFrame`（§8.5 的三种无采样情形，**Q37**）并把段表在解码期按 `startFrame` 升序归一化。`renderer.ts` 的 `trajView` 由字段改 getter，`main.ts` 在 `acceptBinaryPayload` 里 `driver.reset(); driver.apply(traj, 0)`（第 0 帧就位，播放循环仍归 M4-4）。状态与长注见 §9 M4-3 行。
