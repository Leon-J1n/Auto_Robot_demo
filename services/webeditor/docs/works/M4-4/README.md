## 原因与做了什么（PLAN_STATE 备注）

本卡把"播放"从 HTTP 取帧彻底搬到本地。帧源：`timeline.ts` 删除 `TimelineLoader`/`reconstructTimelineFrame`/`CompactTimelineFrame`/`TimelineBundle`（每帧一幅场景快照 + `removedEntities` 增量重建的旧模型），改为 `TrajFrameProvider`：`frame(index)` 先 clamp 到 `[0, totalFrames-1]`，再还原世界父级 → 按帧升序重放 attach → `driver.apply`，所以拖动、帧步进、循环回零、写后重放共用一条幂等路径（Q40）；`simulationTime = index / fps`、`times()` 记忆化，`playhead(current, target, loop)` 收所有时钟判定。驱动侧补齐挂载：`drivers.ts` 新增 `attach(childId, parentId)`（null = §2.5 场景根哨兵；父解析不出返回 false 且不动子节点，与 §8.6"只报 warning 不移挂"一致）与 `restoreParent(objectId)`（读 `Transform.parent`，父为 null 或父已不在场景都回场景根，与 `syncScene` 的兜底同语义），`TrajView` 因此从四查询扩到五查询 `root(): Object3D`（Q41），`renderer.ts` 以 `root: () => this.simWorld` 实现——仍不暴露世界模型。播放循环：`main.ts` 用 `setTrajectory/showFrame/renderPlaybackTicks/updatePlaybackUi/startPlayback/pausePlayback/stopPlayback/playbackControl/tickPlayback/setPlaybackRate/syncRateControls/applyWriteCoexistence` 取代 `setTimeline/showTimelineFrame/tickTimeline/scheduleTimeline/toggleTimelinePlayback`，rAF 里只做"目标仿真时间 = 锚点 + 墙上时间差 × rate"，落后补偿交给 `provider.playhead` + 保留的 `timelineDueIndex`（`timelineDelayMs` 随 setTimeout 排帧一起删除），loop 越界回 0 帧并重新锚定时钟、非 loop 停末帧报 `finished` 自行暂停（Q42）。共存规则收进一个函数：`applyWriteCoexistence(action)` 由 `reply()`（应答写入后、`syncScene` 之后）、`adoptWorld()`（用 `broadcast.action`）、`loadSceneFile()`（手动 Load Scene 视同 `updateWorld`）三个入口各调一次，`updateWorld` → `setTrajectory(null)`（停播 + 清轨迹 + `syncScene` 复原），其余写入 → `showFrame(state.playIndex)` 保持当前帧重放；新 `updateTraj` 由 `acceptBinaryPayload` → `setTrajectory(traj)` 落回 0 帧暂停。UI：播放条补 Stop / 帧步进 ←→ / 循环 / `frame/total` / `time/duration` / 0.25~4 预设 + 连续 RTF（两视图一个数）/ 3 条阶段刻度 + 2 条挂载刻度（hover #### M4-4 播放循环与播放条适配
- **规格**：§7.3、§8.5、§8.6、§8.7
- **涉及**：`timeline.ts`（改为 `TrajFrameProvider`，删除 `TimelineLoader` HTTP 与 `reconstructTimelineFrame`）、`main.ts:setTimeline`(506)、`showTimelineFrame`(约 550)、`tickTimeline`(约 575)、`updateTimelineUi`(约 534)、`#timeline` 模板(89)、`app.addEventListener("input")`(675)、`logic.ts:timelineDelayMs/timelineDueIndex`
- **改动要点**：
  - 帧源换成本地 `TrajFrameProvider.frame(index)`（签名不变，无网络）；`simulationTime = index / fps`。

  - 播放条补：停止并退出播放模式、0.25/0.5/1/2/4 + 连续 RTF、帧步进 `←/→`、`frame/total_frames` 显示、循环开关、`step_count` 阶段刻度 + hover 名称、attach 刻度。（**2026-10-16 更正**：本条前两项"停止并退出播放模式"与"连续 RTF"已由 **Q88** 撤销，播放条只剩五个档位 `<select>`，见 **FEAT-2026-10-16c**；"hover 名称"与两类刻度的双色也由 **Q90** 撤销，刻度改为点击定位，见 **FEAT-2026-10-16d**；其余各项照旧在场。）
  - 与其他写操作共存规则见 §7.3 末条。
  - 删除 `/api/presentation` 模式切换与 `presentation.timeline` 相关代码。
- **DoD**：手测 12.4 全项 + `timeline.test.ts` 重写覆盖"跳帧重放 attach"“空隙帧沿用”"循环回零"。

- **已完成（2026-10-09）**：`timeline.ts` 删掉 `TimelineLoader`/`reconstructTimelineFrame`/`TimelineBundle`，改为本地帧源 `TrajFrameProvider`（`frame(index)` 幂等：还原世界父级 → 按帧升序重放 attach → `driver.apply`），语义与理由见 §13.9 **Q40/Q41**；`drivers.ts` 新增 `attach`/`restoreParent` 与 `TrajView.root()`（第五个查询），`renderer.ts:trajView` 返回 `simWorld`；`logic.ts` 删 `timelineDelayMs`（保留 `timelineDueIndex` 做落后补偿）；`main.ts` 用 `setTrajectory/showFrame/playbackControl/startPlayback/tickPlayback/setPlaybackRate/applyWriteCoexistence` 取代 `setTimeline/showTimelineFrame/tickTimeline/scheduleTimeline`，播放条补 Stop/帧步进/循环/RTF 双视图/阶段与挂载刻度，并删除 `/api/presentation` 模式的死代码（`.sync-mode` 与 `[data-mode]` 分支、`legacy-types.ts` 的 `SceneSnapshot.presentation` 与 `TimelineManifest`）；共存规则收在 `applyWriteCoexistence()`，由 `reply()`/`adoptWorld()`/`loadSceneFile()` 三个写入入口各调一次（**Q42**）。测试：`timeline.test.ts` 重写为 **10 例**（含"跳帧重放 attach""空隙帧沿用""循环回零"三条 DoD + 真实夹具幂等），`drivers.test.ts` +2（14 → 16）。状态与长注见 §9 M4-4 行。
