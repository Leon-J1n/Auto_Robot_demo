## 任务卡原文

### FEAT-2026-11-04-A —— 左栏点一行不再把列表弹回顶部：`#context-content` 收到同一个字符串就一个字节都不写（**Q136**；口径与实装同一张卡；依赖 Q48、Q52、Q93、Q134）

- **起因（用户原话，一次给了三条）**：「进行以下几个修复：1.点击资产列表中的东西后不再让列表回到顶部　2.放置模型时不再考虑机械臂的包围盒　3.添加一个悬浮窗，显示所有相机的拍照内容」。本轮只做第 1 条，第 2、3 条各自一张卡（㊹／㊺）、各自一次本地提交。
- **病因不在点击，在那一次整块重写**：左栏三视图共用 `#context-content`（§7.2），`renderContext()` 每跑一次就把 `renderAssets()` 那一个字符串整个 `innerHTML` 落进去；真正带滚动条的是里面的 `.asset-list`（`styles.css` 那条 `overflow:auto`），旧节点一丢它的 `scrollTop` 就无处可回，每张缩略图 `<img>` 也各自重发一轮 `/thumbnail`。点一次资产行走 `chooseLibraryItem` → `placeAsset` → `selectEntity` → `renderContext()`：**改的是现场，不是这份清单**（`assetRow()` 的 markup 里没有选中态 —— 被选中的是现场里那个物体，不是这一行），于是这一次重渲染得到的串与屏幕上那一份逐字相同，写它零收益、代价正是用户说的那句"回到顶部"。
- **口径与实装同一轮**：`docs/Web前端需求规格v2.md` 新增 **§7.2** 那一条（"三视图共用一块容器、内容由一个字符串整块重写"这一机制第一次写进正文：判据 = 逐字相同就不写、`previous === null` 的首帧总写、为什么层级与 Details 两处照旧重写、`panels.context` 关掉时空串同样成立）、验收 **§12.31**（四层：单测／静态判据／**③ 真浏览器未跑**／负控制与接口面）、决议 **§13.49**。§4.6 与 §4.6.1 本轮**一字未动** —— 那两条讲的是"点一行该发生什么"，本轮讲的是"点完之后那块 DOM 动不动"。
- **实装形态**：`logic.ts` 新增纯函数 `panelMarkupChanged(previous, next)` = `previous !== next`，紧挨 `localAxesEnabled()` 下面（**每一个判断都做成纯函数、才有单测面** —— Q96／Q105／Q119／Q132 同一族）。`main.ts` 三处：导入表 +1、模块级 `let contextMarkup: string | null = null`（记的是"这块容器最后一次真正写进去的是什么"，与当前是哪个视图无关，所以**不按 `state.panel` 分叉**：切走再切回且中间什么都没改，正是应当跳过写的那一种）、`renderContext()` 里那一处 `innerHTML` 赋值套上守卫且**缓存与写入同时更新**（先写后记；记早了会把下一次误判成"没变"）。`renderer.ts`／`placement.ts`／gateway 一行未动。
- **为什么不选另外两条路**：**① 记录并恢复 `scrollTop`** —— 它只治用户说的那一件，治不了缩略图重发与搜索框被抹；它还把"屏幕上的位置"变成第二份要维护的真相，而重写那一刻新节点尚未排版，恢复值会被浏览器按当时尚短的 `scrollHeight` 夹到别处。**② 对 markup 做结构性 diff** —— 需要第二套"什么算同一行"的知识（那是 keyed 协调），而这两个字符串本来就是一次同步构造出来的，比较成本与"内容是否相同"同一个数量级 ⇒ 判据因此就是一条恒等。**③ 反过来"每处 DOM 写都加守卫"** —— 只在 `#context-content` 这一处立判据；`#panel-count` 那类 `textContent` 不影响滚动，铺开只会把一条判据变成十处。
