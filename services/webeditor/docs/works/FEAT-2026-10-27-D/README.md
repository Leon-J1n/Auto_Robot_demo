## 任务卡原文

### FEAT-2026-10-27-D —— Agent 输入框的回车 = 点发送（**Q129**；新卡 ㊱；依赖 FEAT-2026-10-27-C）

- **起因（用户原话）**：「当光标聚焦在Agent面板的输入框中时，按回车键等同于点击发送」。这条诉求里没有 bug，要选的只有两件事：**"等同于"在实现上做到多字面**，以及**哪几次回车不算发送**。
- **"等同于"落成 `form.requestSubmit()`**：键盘那条分支不调 `submitAgent`、不读输入框、不清空，它只做一件事 —— 让这枚 `<form id="agent-form">` 自己派发 submit。于是 `enabled("agent.input.send")` → `void submitAgent(input.value)` → `input.value = ""` 这**一份**实现同时服务按钮与按键，空文本的 `Agent command cannot be empty`、会话正在创建时 `submitAgent` 那道 `sessionCreationInFlight` 的回执、请求 body 的五个字段，全都是**点击本来会给的那个回答**。**不做的事**：复制第二套发送逻辑（早晚裂成"点按钮对、按键不对"）、给回车另加一个 feature 键、改 `POST /api/agent/jobs` 的形状。接管条件是 `logic.ts:enterSendsAgentMessage(features, key)` 一个纯函数（六个字段的合取），`main.ts` 只把事件字段抄给它、再照回答决定 `preventDefault()` 与否 —— 与 §4.8.5 的 `shadowsEnabled`、§4.8.6 的 `boundingBoxesEnabled` 同构，这就是本条**有单测面**的物理原因（卡 ㉞ 那句"`main.ts` 的时序没有单测面"仍然成立，本条不在时序里）。
- **四次回车不接管（判据都在否定式里）**：**① `Shift+Enter` 仍是换行** —— 输入框是 `<textarea rows="3">`，把两件事压成一条键就没有"写一条带步骤的命令"的入口了；**② 输入法候选那次回车**看 `isComposing` —— 中文输入法按回车是在选定候选词，不写这条等于用户每打完一句中文就把半句话发出去，这是本轮唯一会让"回车 = 发送"变成缺陷的地方；**③ 按住不放**看 `repeat` —— 一次点击不会重复，一根按住的手指不该变成一串任务；**④ `Ctrl/Meta/Alt+Enter`** 归浏览器与操作系统。**第五件事不是否定式而是选择**：`agent.input.send: false` 时这条键路直接 return 且**不** `preventDefault` ⇒ 回车回到浏览器默认（换行），而不是"按钮被关掉却仍吃掉一个键"；与卡 ㉜ 的 `viewport.record:false`（点击在委托闸门就被丢掉）同一条口径，差别只在键盘这一侧选择把默认行为还给浏览器。R2「点击必须有响应」在键上的形态即此：接管时走 submit 那条链（成功出气泡、失败出告警），不接管时走浏览器默认 —— 两种回答都不是沉默。
