## 1. 用户口径原文（2026-10-31，本卡的唯一需求来源）

> 下面我们要在前端实现摆放物体和切换机械臂的功能，此功能只在当前会话中用户第一次给 Agent 发送消息之前生效。我们可以通过 OLS 中的 `/robot?id=xxx` 或 `/model?id=xxx` 接口来访问对应机械臂或模型的元数据。当用户在资产面板中点击一个模型时，如果当前场景是空场景，首先加载 OLS 中 id=1 的场景，然后在桌面上随机位置放置这个模型；如果场景非空，在桌面上随机位置放置这个模型（不能和其他模型碰撞）。当用户在资产面板中点击一个机械臂模型时，如果当前场景是空场景，首先加载 OLS 中 id=1 的场景，然后将场景中的机械臂替换成指定机械臂；如果场景非空，将场景中的机械臂替换成指定机械臂，所有机械臂均假定为单臂，因此替换时只需要读取 `scene_one_arm` 中的信息。当用户点击一个夹爪时，将当前机械臂连接的夹爪换成指定夹爪。当用户点击一个相机时，将相机替换成指定相机。在替换时，注意：机械臂要放在距离桌子长边指定偏移的位置（即 `robot_pose_percent_compared_to_table_length_center`），部分机械臂可能有底座，由于桌子位置已知，机械臂和桌子的相对位置已知，我们假定底座包围盒的上边缘和机械臂包围盒的下边缘重合，底座模型的缩放值已知，因此可以得到底座模型的位置。在编写带有 urdf 的物体的 `RobotDriver` 组件时，如果元数据中有 `robot_driver` 相关的信息，可以直接采用，否则，需要从 urdf 中读取。在编写夹爪和机械臂的链接信息时，注意，`RobotAttachment` 的 `child_link` 信息在 `robot_driver.robot_attachment` 中，`parent_link` 等信息在相应机械臂的 `robot_driver` 中。如果没有提供相应的数据，我们可以假定：假设 urdf 是一个树形结构，那么树的根节点可以当做 `child_link`（例如 `robotiq_2f85_mount`），树的叶节点可以当做 `available_connect_link`（例如 `wrist_3_link`）。在实现本任务时，新建一个任务卡，不要和以往的任务卡放在同一个文件里。每完成一个功能，在 master 分支进行一次本地提交。

## 2. 本轮的六个判断（写进 §13.47 的八处口径，这里记来历）

1. **生效窗口不新立判据**。用户那句"只在第一次给 Agent 发消息之前生效"与 §4.6 已有的阶段闸门（`CLASS_TWO_ENTRIES = '[data-action="load-scene"], [data-asset-kind]'` + `logic.ts:sessionPhase`）说的是同一件事，且 `[data-asset-kind]` **早已在那条闸门里**。⇒ 本轮**不加闸、不改弹窗口径**。
2. **`geometric_properties.AABB` 是六个浮点的三对无序端点**。读第一版把它当"min,max 有序"，于是底座 `[…, 0.25, -0.25]` 那种一对都正的出厂值算出负边长。改成 `library.ts:readAabb` + `Aabb6` 逐对取 min/max；非六个有限数按"没有包围盒"处理。
3. **臂位按"朝向盒"读，不按声明值**。出厂七个场景的工作台都在 `[0,0,0]`、单位四元数、单位缩放，两种读法给同一个数；本仓库夹具 `docs/ur5e_table_empty.json` 的桌子站在 `x=0.525`，两者立刻分岔。⇒ 正文与测试一律按 `orientedBox()`（打过父链位姿的世界盒）写。夹具属 §8 禁令，**不改**。
4. **基准点是那条长边的中点，三个 offset 都加在它上面，加完的那一点就是臂的原点**（用户 2026-10-31 两次更正后的口径，见 §6 那两段追加）：`[cx ± p0·Lx, box.min.y + p1·Ly, box.max.z + p2·Lz]`；预制场景 3 那张站在 `[0,0,0]`、`1.5 × 0.75 × 0.6` 的桌子 ⇒ 中点 `(0,-0.375,0.6)` + `offset [0.3,0.225,0.3]` ⇒ **`[0.3, -0.15, 0.9]`**，夹具那张搬到 `x=0.525` 的桌子 ⇒ `[0.825, -0.15, 0.9]`（双臂镜像只在 X 取负）。**替换机械臂时不检查放置的合理性**（用户口径：现在这些百分比是占位数，正式版保证合理）⇒ 臂与底座这一路只算不判，`y=-0.15` 压在桌面 `y` 范围之内是预期结果，碰撞避免只作用于道具那一条 `spotOnTable` 路径。**与出厂手写坐标的对照如实记在 §12.30 ⑤ b**：piper/cobotmagic 手写 `[±0.3, -0.33, 0.6]`、ur5e 手写 `[0, -0.5, 0.57]` —— 只有 x 复原得出（且它在中点/中心两种基准下同值，不能用来裁决），y、z 是作者按各台臂的底座手调的。⇒ §4.6.1 与 §12.30 ⑤ 明写**这一条是按 OLS 随键写的那句定义走的口径选择，不是复原出厂坐标**。出厂十一台臂里有四台的盒底压在自己原点以下（baxter −0.9242 最深，另三台 ur10 −0.0347 / ur3 −0.0007 / pr2 −0.0002），所以"该点即原点"与"盒底落在该点"确实不是同一条 —— 判据挑了 baxter 把差别钉住。
5. **底座缩放照 `pedestal_scale` 声明值写，缺该键才 `[1,1,1]`**（用户 2026-10-31 第三条口径：「底座的缩放要尊重 `pedestal_scale` 属性，如果没写，默认(1,1,1)」）：出厂十一台臂声明的全是 `[1,1,1]`，底座盒 `z ∈ [-0.25, 0.25]` ⇒ 盒跨 `[0.4, 0.9]` —— **顶沿精确贴在臂盒底 0.9，底沿悬在地面以上 0.4**。本卡初版在这里加过一步 `max(声明, 臂盒底 / 盒高) = 1.8` 的放大（好让底座同时顶住地面与臂盒底），**已被这条口径推翻、代码里删掉了**；那条放大本来就是替占位数值补的洞，而占位数值归 OLS 侧管（§2 第 4 条）。模板作者手写的 **1.28**（底座位姿 `[0,-0.5,0.25]` ⇒ 盒跨 `z ∈ [-0.07, 0.57]`：**顶沿与那台 ur5e 的盒底 0.57 精确重合**，底沿沉到地面下 0.07）与本规则同一个取向：照声明写、只约束顶沿。
6. **夹爪的空连接表是声明，不是缺失**。最初我加了一条 `needsUrdfRead()` 把"表是空的"当成缺失去读 URDF，于是一次夹爪点击把四连杆的树当成了臂的树，测试报 `expected 'arm' to be 'gripper'`。按用户原话收窄回**"元数据里没有 `robot_driver` 才读 URDF"**，并在单测里用 `source.reads` 为空数组把这件事钉成可测事实。

## 5. 遗留与差异（下一轮接手前必读）

1. **§12.30 ③ 的四格 A/B/C/D 没有实测数字** —— 只有单测与代码路径。要么修好坑 90 那道身份闸让 `browser_smoke.cjs` 跑起来，要么再走一次一次性手工探针（上一轮 Q133 就是这么做的：临时网关 + 现成 `dist/`，用完就杀）。
2. **夹具与真实 OLS 的桌子位置不一致**（`x=0.525` vs `[0,0,0]`）：本轮**按夹具写断言、按朝向盒写口径**，同一组百分比在两边分别给出 `[0.825, -0.15, 0.9]` 与 `[±0.3, -0.15, 0.9]`。若哪天夹具更新成出厂形状，这些数值断言会一起变，**判据形状不用动**。
3. **出厂那两份臂位手写坐标与本规则算出的点仍然不一致**（piper `[±0.3, -0.33, 0.6]` vs `[±0.3, -0.15, 0.9]`：x 逐位相同，y 差 0.18、z 差 0.3；ur5e `[0, -0.5, 0.57]` vs `[0.3, -0.15, 0.9]`）。用户 2026-10-31 已就此给出口径：现阶段的百分比是**占位数**、正式版由 OLS 侧保证合理，⇒ 本卡按式子算、不复原出厂坐标；这条差异**不再列为待裁决项**，用户已裁定按声明的百分比算。本轮**按用户口径与 OLS 随键写的那句定义算，不按出厂场景文件里那几个手写的数算** ⇒ 点一次臂就会把现场那台臂从作者写的位置搬到规则算出的位置（底座照它自己声明的 `[1,1,1]` 写，于是顶贴臂盒底、底悬在 0.4 半空中 —— 见 §2 第 5 条）。如果 OLS 那七份出厂场景才是权威，那它们需要按这条式子重新生成 —— **这是留给用户裁决的一条**。
4. **相机替换只换 `MetadataRef`**，内参与视点保持作者写的值 —— 这是本轮的判断（§13.47 ⑧ 那句"视点由画面作者定"）。若需求是"换成该相机资产自带的视点"，那是另一条口径。
5. 双机模板的第二台臂沿**长边方向（X）镜像**（`side = −1`，y/z 两轴不动）—— 与出厂那两份双臂场景 `[±0.3, -0.33, 0.6]` 的镜像轴一致。出厂双臂场景里那两台是同型号，所以这个镜像只影响"现场只有一台臂时点同一型号"这一条路径。
