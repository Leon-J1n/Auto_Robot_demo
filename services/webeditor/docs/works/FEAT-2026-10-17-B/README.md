## 任务卡原文

### FEAT-2026-10-17 —— 幽灵的两处改判：浓淡进常量、集合含夹爪（Q97/Q98）（新卡；依赖 FEAT-2026-10-17-A）

- **起因（用户原话）**：「将幽灵不透明度设为一个配置参数在config/constant_config.json中，默认值50%；机械臂的定义为带有RobotDriver的所有物体，所以夹爪也应该有幽灵显示」。一句话里两件事，分开记：**Q97**＝浓淡从字面量 `0.2` 改成常量 `ghost_pose_opacity`（默认 `0.5`），**Q98**＝幽灵的对象集合从「clip 里第一台带段的机械臂」改成「clip 里每一个在世界中带 `RobotDriver` 的物体」。**Q98 就地推翻了上一张卡「明确不做」的第一条**（不给多臂画多台）—— 那张卡的字面保留作历史，本卡是现行口径。决议记 **§13.27**，正文就地修订 **§7.3 第 1/3/7 条**、**§9.2**、**§12.12**（拆成现场 A/现场 B、七条改九条）。**`features.json` 不增不减（仍 80 键）**：关断归 `playback.ghostPose`、浓淡归常量，两件事不混在同一个键里，所以 `docs/feature-inventory.csv` 本轮不重生成。**但 `docs/parity-probes.json` 重生成并入了本次提交**：那份快照记的是 `/api/runtimeConfig` 实际回读到的键数，加常量之后是 **13 → 14**，留着 13 就是「记录 13 个键、真实响应回 14 个」的自相矛盾；它本来就是每轮 `tools/parity_inventory.py` 的固定产物（与 **Q96** 那张卡一致）。
- **Q97 是一条五处落点的管道，不是一行数字**：`config/constant_config.json:18` ↔ `local_gateway.py:50`（`DEFAULT_CONSTANT_CONFIG`，缺字段时由它兜底）↔ `GET /api/runtimeConfig` 原样下发 ↔ `contracts/types.ts:351` 与根 `types.ts:351`（`RuntimeConfig.ghost_pose_opacity?`，两份逐字节同步，**坑 6**）↔ `editor/src/logic.ts:ghostOpacity()` ↔ `renderer.buildGhost(objectId, opacity)` → `ghostAsset(root, opacity)`。**两份默认值不会漂移**，因为 `tests/test_gateway_routes.py` 早就钉着 `load_constant_config() == DEFAULT_CONSTANT_CONFIG`（本轮在该用例里补一条 `config["ghost_pose_opacity"] == 0.5`，python 例数不变）。**为什么判据是 fail-open**（与 **Q81** 的 fail-closed 相反）：`ghostOpacity()` 只接受有限且落在 `[0,1]` 的数，缺字段 / `null` / 字符串 / `NaN` / 越界一律回 `DEFAULT_GHOST_OPACITY = 0.5` —— 这里没有「不认识这个键就该收回能力」的安全含义，读不懂只能解释成「没人调过它」，那就该看到默认浓淡。`0` 是合法值（用常量把幽灵调到看不见，留作运维手段），`§12.12` 第 ⑨ 条正是拿 `0` 与「flag 关掉」**逐字节相同**来证明这条常量真的通到了材质，而不是只通到了某个 `if`。
- **Q98 的改判被真实数据推着走**：OLS 的 7 份场景**每一份**都恰好两台 `RobotDriver`（`2=UR5eArm` + `3=Robotiq2F85Gripper`，scene 5 是 `CobotMagicLeft`/`CobotMagicRight`），而 `examples/scene3_9_segments.traj` 的夹爪开合**正是**由 object 3 自己那两条段驱动的（TRAJ 第 7 分量按 **O1** 只记录不驱动几何）—— 只画第一台等于把「这一段结束时夹爪是张是合」这条信息整个丢掉。**推翻成本一行**：`main.ts:ghostTargets()` 里那个 `.filter(object => state.world.robotDriver(object.objectId))`，改回旧口径就是 `.find()` 取第一个。**同时放宽了一条**：不再要求该物体自己有段 —— 没段时 `poseAtFrame` 回落默认位姿，那台幽灵与真机重合，等于没画（口径写进 §7.3 第 7 条，避免"为什么不画"变成隐性规则）。
- **多台幽灵必须共用同一个「当前段」**：`stepAtFrame` 的输入是 `Traj.steps`（`stepsFrom(objects)` 跨物体并出来的那一份，刻度也画它），不是逐物体各自的段表 —— 于是臂（9 段）与夹爪（2 段）的幽灵永远指向**同一个帧号**。这一点不显眼但决定成败：若各自查自己的段，两台幽灵会在不同的帧上"预告"，画面上就是两台幽灵互相分叉。
- **「幽灵跟着幽灵」是这条改判真正的技术内容**：夹爪的真机父节点是机械臂的 `wrist_3_link`（**静态 `RobotAttachment`，不是运行时 Attach** —— 真实场景 3 本来就这样，所以每帧都得重算，不能挂在 Attach 事件上做一次性补丁）。若幽灵夹爪仍留在**真机**的腕上，就会出现「半透明夹爪停在播放头那一帧的腕上、半透明臂伸到段末」，两台幽灵分叉成两个地方，功能当场失去意义。落点：`renderer.ts:ghostParent(objectId, liveParent)`（遍历**其他**幽灵，谁的树包含这个真机父节点，就按 `UrdfTree.links` 的 **link 名**换到那台幽灵树里的同名 link）+ `rehangGhost()`（每帧 `syncGhost()` 调，顺带拷 `position/quaternion/scale`）+ 模块级 `isWithin()`（`renderer.ts:288`，判「这个节点在那棵树里」）。**解析不到对应 link 时退回真机父节点** —— 宁可挂错位置也不让幽灵消失。
- **renderer 从「一台」到「每物体一台」的结构改动**：`ghost?: UrdfTree` → `ghosts: Map<number, UrdfTree>` + `ghostLoading: Map<number, Promise<boolean>>`（同 id 的并发 `buildGhost` 复用同一份在飞 promise）+ `ghostGeneration: Map<number, number>`（作废令牌）。`retainGhosts(keep)` 取代「整台清掉」，`main.ts` 每帧把当前集合递进去，于是换臂、`playback.ghostPose` 关断、清除轨迹三条路径共用同一个入口。`isEditorOnly()`（`renderer.ts:1097`）的身份判据从 `object === this.ghost?.root` 改成 `object.userData.ghost === true` —— **仍然只有一条判据**（多实例后不能再比单个 root，`ghostAsset()` 在克隆材质时顺手给每个子节点打标），`/captureScene` 的 `hideOverlays` 因此照旧自动覆盖两台幽灵。
- **自查修掉的两个真 bug（都在"静默不出现"这一族）**：(a) `stale()` 最初直接读 `this.ghostGeneration.get(objectId)`，而从未被幽灵过的物体在 Map 里是 `undefined`，与起始代 `0` 不相等 ⇒ **每一次构建都在展开完的那一刻被判成"已作废"并 dispose**，8 个用例同时红、`buildGhost` 一律 `false`，症状是「幽灵永远不出现且不报错」。改成读写同源的一个函数 `ghostGenerationOf()`（`?? 0`）即好（**坑 63**）。(b) `clearGhost()`/`retainGhosts()` 原来只遍历 `this.ghosts`，**在飞的那份没人取消** —— 切走轨迹之后晚到的资产照样挂上去，端上多出一台没人认领的幽灵。改成 `ghostIds()` 取 `ghosts` 与 `ghostLoading` 两表键的并集，并在 settle 处按 promise 身份判据删 loading（否则旧构建的收尾会把新构建的 loading 条目抹掉）。
- **测试（vitest 343 → 348 例，全绿）**：`logic.test.ts` +2（`ghostOpacity()` 的接受域 0.2/0/1 原样通过；缺字段/`null`/字符串/`NaN`/越界一律 `DEFAULT_GHOST_OPACITY`，并钉住该默认值就是 `0.5`）；`renderer.test.ts` +3（**两台幽灵并存且夹爪那台改挂到幽灵臂的 link 上** —— 手工把真机夹爪节点 `add()` 到臂的 `link1` 下，正是 `worldParentOf`/`attachTarget` 在真实场景里做的事，然后断言幽灵夹爪落在 `ghostTree(1).links.get("link1")` 而不是真机腕上，`retainGhosts(new Set([2]))` 之后又退回真机腕；`retainGhosts` 只留要的那几台；被 `clearGhost()` 取消的在飞构建返回 `false`、`ghosts` 里没留、场景里也没有 `userData.ghost` 残节点）。既有用例的改动只有一处性质：透明度从「断言等于 0.2」变成「断言等于传进去的那个值，且真机材质仍 `opacity=1`/`depthWrite=true`」—— 材质互不污染这条比 Q96 更硬，因为现在两侧都是同一份克隆链路。
- **真机取证（§12.12 现场 B：两台 `RobotDriver`）**：现场 = **§12.12 现场 B** —— 世界取 OLS 库文件 `GET /scene?id=3` 的 objects `0/14/2/3/7` 那份**逐字节子集**（`scene3_pair.json`：环境光 + 顶光 + `2=UR5eArm` + `3=Robotiq2F85Gripper`（静态挂在 `wrist_3_link`）+ `7=Apple`），clip = `examples/scene3_9_segments.traj`（840 帧 / fps 60 / 载入后 **11 根刻度**）。完整 14 物体的场景 3 会把 swiftshader 标签页压垮（**坑 64**），而裁出来的这五个对象与库文件一字不差，Q98 要的两台 driver 与那条静态 `RobotAttachment` 全都在。**五个 pass 各起一个新浏览器**（默认 0.5 / flag 关断 / `0.9` / `0.05` / `0`）：`/updateWorld` 与 `/updateTraj` 全 200、`ignored_objects: []`、`warnings: []`、`pageerror` 五份全空、层级树在载入 clip 前后恒为 `5/5`、`/getWorld` 的 id 恒为 `[0,14,2,3,7]` —— **两台幽灵都不在任何对外通道里**，这是 Q96 那条判据在两台情形下的复验。
