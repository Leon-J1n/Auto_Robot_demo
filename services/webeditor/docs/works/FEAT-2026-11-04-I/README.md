## 任务卡原文

### FEAT-2026-11-04-I —— 摆放：随机放不下时确定性扫遍桌面 + OBJ 模型按真实顶点定碰撞盒（**Q144**；修复与验收同一张卡；依赖 Q134、Q137、Q143、Q105/Q119）

- **起因（用户原话，一条报告里两个 bug）**：「发现摆放物体功能中的两个bug:1.摆放时有时随机的位置不能放下物体，于是提示放不下。但桌子上还有很多能放下的位置。往往下一次随机到一个更好的位置就能放下了。我希望你先尝试随机摆放，如果失败则在桌面上尽可能寻找能放下的位置，如果实在找不到才提示放不下。 2.有的物体摆放时出现穿模，目前model/23号物体能稳定复现。检查原因并修复」。**两个 bug 落在同一条 `spotOnTable` 与同一份 footprint 上**：bug 1 是"取点放弃得太早"（随机全落空就报放不下），bug 2 是"量 footprint 用的那个盒不是画出来的那个盒"（元数据 AABB 与网格不在同一个轴系）。
- **诊断（bug 2 这一步要对着用户拥有的那份出厂数据逐份量，不能凭 model 23 一份猜）**：`model 23` 那只杯子的元数据 `geometric_properties.AABB` 写成 `[0.065113, -0.065627, 0.046532, -0.04999, 0.114619, -5e-06]`，按 §4.6.1 的 `[x+,x-,y+,y-,z+,z-]` 读法是 `x[-0.0656,0.0651] y[-0.0500,0.0465] z[0,0.1146]`；而它发货的 `mug.obj` 真实顶点量出来是 `x[-0.0500,0.0465] y[-0.0651,0.0656] z[0,0.1146]` —— **Z 逐字相同、X 与 Y 两个范围互换**。摆放用元数据 AABB 量 footprint（先按 `TABLE_YAW` +90° 转角再量），占位盒因此相对画出来的网格转了 90°，两只"纸上只贴边"的杯子在屏幕上叠了约 **3.4 cm**（穿模）。**这不是 model 23 一份手滑**：把 `ObjectLibraryServer/data/models` 下 **25** 份顶层 OBJ 模型（`_files.json` 的 `path` 以 `.obj` 结尾的那 25 个；另 6 个顶层是 URDF／其它）逐份比对元数据 AABB 与 `objVertexBounds` 量出的网格盒，**9 份对不上**（`4 basket`、`8 gum_bottle`、`9 cream`、`14 mug`、`18 coffee_table`、`21 test_tube`、`22 toy_panda`、`23 mug`、`24 mug`）—— 多数是 X/Y 互换（`22 toy_panda` 是严格互换），`18`／`21` 是 up 轴错位（元数据把高度写在 Y、网格写在 Z）。**一处必须先证的前提**：`parseAsset` 的 OBJ 分支**不做任何逐资产旋转**（只有 DAE 的 `Z_UP`、FBX 的单位缩放有补偿），整份世界的 Z-up→Y-up 只在最外层 `simWorld` 转一次（`SIM_WORLD_TILT`，§4.4／Q135）⇒ **OBJ 文件的那个帧就是元数据 AABB 声称的那个 Z-up 局部帧**，`objVertexBounds`（文件帧）与元数据 AABB 直接可比、顶替是帧一致的（model 23 的 Z 逐字相同正是这一条的实证）。
