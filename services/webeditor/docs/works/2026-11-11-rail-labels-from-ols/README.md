# 2026-11-11 导航栏大类文字严格取 OLS 第一层分类

## 原因

用户原话：「导航栏中的文字要严格按照 OLS 中分类的第一层分类写，如：场景、模型、机器人。」

Q156 把三大类搬上导航栏时，按钮文字沿用了面板时代前端自己起的名字 —— **预设场景 / 预制模型 / 机械臂**。这三个词不是 OLS 的说法。实测装机库三个索引里 `category` 的**第一层**：

| id 空间 | OLS 索引里的 `category`（去重） | 第一层 |
|---|---|---|
| scene | `场景.桌面操作` | **场景** |
| model | `模型.果蔬` / `模型.玩具` / `模型.生活用品` / `模型.文具` / `模型.工具` / `模型.食品` / `模型.实验器材` / `模型.家具` / `模型.餐具` | **模型** |
| robot | `机器人.单臂` / `机器人.夹爪` / `机器人.摄像机` / `机器人.底座` / `机器人.背景` | **机器人** |

**`docs/OLS接口.md` 是错的**：`/presignUploadID` 那条写「类型前缀按 type 取 模型/机械臂/场景」，而真实 robot 索引里全是 `机器人.*`。用户给的三个词与数据一致，与那份散文不一致 —— 以数据为准（同族：坑 113/115）。

## 做了什么

- **就地修订规格**：
  - §4.7 新增一条（决议号 **Q159**，改判 Q156 落笔时用的三个词）：按钮文字 = OLS `category` 第一个点之前那一段；写明实测三词、写明接口文档那句与数据不符、写明判据与刷新点。
  - §4.7 上一条与 §7.2 第一条里的「预设场景 / 预制模型 / 机械臂」改成「场景 / 模型 / 机器人」；§4.6 那句「场景 / 模型 / 机械臂这三个大类」同步改成「机器人」。
- `editor/src/assets.ts`：
  - `GROUP_LABELS` 改成 `{ scene: "场景", model: "模型", robot: "机器人" }`，语义从"前端起的展示名"变成"**OLS 尚未答复或不可达时的回落值**"。
  - 新增纯函数 `kindLabel(kind, categories)`：按 `/listCategory` 发布的顺序取**第一条带点**类别的首段（`dot > 0`，所以 `.桌面操作` 这种空首段不算），一条都没有时回落 `GROUP_LABELS[kind]`。**OLS 改了第一层的叫法，按钮跟着改，不用改前端。**
- `editor/src/main.ts:renderContext()` 的 `[data-panel]` 循环里补一句：带 `data-asset-kind-nav` 的按钮把 `<span>` 文字写成 `kindLabel(kind, state.library.sections[kind].categories)`。**刷新点必须在这里而不是模板里** —— 真实文字要等 `/listCategory` 回来才知道，而 `refreshLibrary()` 拿到清单后本来就会再 `renderContext()` 一次，等于零新增渲染路径。
- `tools/browser_smoke.cjs` 的标签断言改成 `['场景','模型','机器人']`。
- 测试：`assets.test.ts` 新增 4 支 `kindLabel` 用例 + 改判常量那支；`asset_rows.test.ts` 新增 1 支源码级接线用例（刷新语句在 `renderContext` 里、`refreshLibrary` 落库后确实再渲染、回落常量就是这三个词）。

### 不做

- 不改 §4.6 里 **预设场景 / 预制模型 / 机械臂** 那三条**行为** bullet 的小标题：它们描述的是三个 id 空间点击后干什么，不是界面字符串，全篇改名属于另一件事。
- 不改面板标题 `LIBRARY / Assets`、`#panel-count`、分类栏宽度。
- 不新增功能键、常量、路由或协议字段；Gateway 与 OLS 都一个字未改（只读它的索引做核对）。
