### FEAT-2026-11-04-H —— 面可以引用文件里还没出现的顶点：交给 `OBJLoader` 之前先把整份文件规范化（**Q143**；口径与实装同一张卡；改判卡 ㊽ 两条腿里的那一条；依赖 Q141、Q119、Q105、Q72）

- **起因（用户原话，两次）**：「重启后出现了一个提示：robotiq_2f85_meshes/silicone_pad.obj: silicone_pad has vertices that are not numbers -- the file declares them after the faces that index them. The box and the picking u... 不再显示这个提示。另外，对于这种顶点写在引用的面之后的资产，我们能否读入完整文件后整体解析？这样就无需处理这种情况」＋「在第一遍的时候直接做规范化，这样即使后面有新的资产使用了负数索引也无所谓」。**两句里各有一个决定**：第一句否掉卡 ㊽ 那条告警、并给出方向（"读入完整文件后整体解析"）；第二句把这条路要做对的那一处点了名 —— **负数索引**。
- **为什么"整体解析"可行（这一步要先证，不能直接写）**：OBJ 的正索引是**绝对的**、从文件头数起（`f 12` = 文件里第 12 个 `v`，不是"到这一行为止第 12 个"），所以把全部 `v`/`vn`/`vt` 声明排到第一条面语句之前**不改变任何正索引指向谁** —— 这不是绕过资产缺陷，是按格式本来的语义解析，`OBJLoader` 只是选择了单遍读。**负数索引是唯一的例外**：`-1` = "**此处**已声明的最后一个"（loader 自己按 `index + len/3` 解、`vt` 用 `len/2`），搬动声明会**悄悄**改掉它指向谁 —— 不报错、不 NaN，只是一份形状不对的网格，比原来的 NaN 更难查。按用户点名的那一手，**同一遍**把每个负数索引写成它已经意味着的那个绝对索引（`declared[slot] + value + 1`，与 loader 的算式同解）；就地已越过文件头的那个（`absolute < 1`）**保持断掉**，不替它造顶点。此后"声明写在哪儿"对任何文件都不再有意义（**坑 114**）。
- **触发判据按病灶写，不按形状写（本轮最容易做过头的一处）**：判"有面索引了此处尚未声明的顶点"⇒ 出厂库**恰好 6 份**（卡 ㊽ 数出来的那 6 份 robotiq）；判"任何 `v`/`vn`/`vt` 出现在第一条面之后"⇒ **28 份**，多出来的 **22** 份是合法的分块资产（d455、d435i、ur3 visual ×7、ur10 visual ×5、dobot_cr5 Link1–5、nero link2/4/5），就地解析完全正确 ⇒ 松判据白白重写 22 份好资产（**坑 115**）。**不需要改动的文件原样返回、逐字节相同**（210 份里 **204** 份），于是"其余资产没被这轮碰过"是一句**可复核**的话（单测 `toBe(source)` + 真实库逐份比对），不是一句保证 —— 这也是本轮不需要逐资产回归的理由。
