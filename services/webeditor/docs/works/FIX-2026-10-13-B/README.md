## 原因与做了什么（PLAN_STATE 备注）

FIX-2026-10-13 维护卡第 ② 张：相机光学系定为"局部 +Z 前、+X 右、+Y 下"，推翻旧口径"+X 前、+Z 上"（决议 Q70，规格 §4.4 补一条正文，`docs/场景文件描述.md` §3/§4.6 两处改写）。定方向的证据：`robots\3` 的 `d435i.obj` 顶点 z 区间 `[-0.0251, 0]`、x 跨 0.090 m、y 跨 ±0.0125（真机 90×25×25 mm）⇒ 镜头面在 z=0、机身朝 −Z，前方只能是 +Z；`docs/ur5e_table_empty.json` 俯视相机 `[1,0,0,0]`（绕世界 X 轴 180°）在旧口径下不改前方＝朝天，新口径下恰好翻 +Z 成垂直俯拍，腕部 `[0,0,1,0]`（绕父链 Z 轴 180°）光轴仍沿夹爪接近方向。旧口径的可观测后果是"互相矛盾而不是一片报错"：视锥线与预览看着都正常，但 `/captureScene?id=5` 出地平线、`/get2DAABB?id=1&camera_id=5` 得 `visible:false`。改动只在两处（约定必须有一份）：`logic.ts:cameraFrustumSegments` 角点沿 +Z 展开、`renderer.ts:sensorSetup` 的 `up` 取 `(0,-1,0)` 旋转且 `lookAt` 目标取 `(0,0,1)` 旋转（映射行列式 1，不镜像）；在 gizmo 里补 90° 是最坏修法，写进坑 31。真机取证（vite 5173 + gateway 8080 + OLS 8000，页面内 `fetch`）：俯视出图变成"桌面沿画面竖直展开、机械臂在 −X 一侧"，与"画面右 = 世界 +X、画面上 = 世界 +Y"自洽；`/get2DAABB?id=1&camera_id=5` 由 `visible:false` 变 `visible:true, clipped:false`（盒 `x 181.4~389.3 / y 32.2~447.8`），腕部 `camera_id=4` `visible:true, clipped:true` 且夹爪在画面上方（相机偏装 −Y 一侧 ⇒ 画面下 = +Y，对得上）。同批重标定四处把旧口径写死成数字的夹具：`renderer.test.ts` 的 `aabb projection` 整组搬到 +Z 前方、`logic.test.ts` 视锥角点断言（72 点、远面首角 = 半宽/半高/far）、`tools/browser_smoke.cjs` 相机 `[-3,0,0]`→`[0,0,-3]` 保持单位四元数（"identity 即看向 +Z"成为可执行断言）、§12.6 clipped 探针从 Y 轴挪到 X 轴（画面右现在是 +X）且 behind 改 `z=-6`、§12.5 的 `fromSensor` 改 `hypot(x, y, z+3)`。验证：`tsc --noEmit` 0 错、vitest 260 例 / 12 文件、`npm run build` 通过、`node tools/browser_smoke.cjs` 8 项全绿（§12.5 深度 2.9700 对中心距 3.0545 ⇒ 2.76% < 5%、NaN 306 219；§12.6 clipped 盒 `x_max=640` 贴右边界）。显式待确认（不假装已定）：绕光轴的 roll 有两个右手系解，资产与场景几何都对称、画面无法区分，本卡按 OpenCV/ROS 取 +X 右/+Y 下；若 Sim Core 用 +Y 上，改动是 `sensorSetup` 的 `up` 与 `cameraFrustumSegments` 的 Y 分量各取反一行。
