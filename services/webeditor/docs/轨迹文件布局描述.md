# 轨迹文件布局描述（TRAJ v2）

本文档描述 `轨迹文件生成器.py` 输出的 `.traj` 二进制格式，并以实际样例
`app/robot_grasp.traj`（12088 字节）逐字段核对偏移与取值。

- 生成脚本：`轨迹文件生成器.py`
- 输入配置：`app/config/robot_params.json`、`app/config/scene.json`
- 运动学模块：`ur_kinematics.py`（IK 求解，决定 `A~E` 五个关键位姿的关节角）
- 消费端解析器：`app/index.html`（`parseTrajectory()`，小端 `DataView`）
- 场景：UR5e 机械臂抓取苹果放入盒子

---

## 1. 总体布局

文件由 4 个连续区域组成，**全部小端序（little-endian）**，区域间无填充：

| 区域 | 样例偏移 | 样例长度 | 说明 |
|------|----------|----------|------|
| Header | 0 ~ 32 | 32 B | 定长文件头，8 个 `uint32` |
| Index | 32 ~ 296（`indexOffset`） | 264 B | 每物体一段索引：对象头 + 默认位姿 + 段表 |
| Attach | 296 ~ 328（`attachOffset`） | 32 B | 挂载事件表，每条 16 B |
| Data | 328 ~ 12088（`attachOffset + 16×attachCount`） | 11760 B | 各段姿态数据，`float32` 紧密排列 |

```
0        32                              296   328                        12088
┌─────────┬───────────────────────────────┬─────┬──────────────────────────┐
│ Header  │  Index  obj1 │ obj2 │ obj3    │Attach│          Data            │
│  32 B   │         (每物体 40/40/184 B)  │ 32 B │  420 帧 × 7 × float32    │
└─────────┴───────────────────────────────┴─────┴──────────────────────────┘
```

Index 内部按物体顺序排列，每个物体贡献 `12 + poseDim×4 + 16×segmentCount` 字节；
Data 内部按 Index 中各段出现的顺序追加写入，段的 `dataOffset` 为**绝对文件偏移**。

---

## 2. Header（32 字节）

`struct.pack('<8I', ...)`

| 偏移 | 字段 | 类型 | 样例值 | 含义 |
|------|------|------|--------|------|
| 0 | `magic` | u32 | `0x5452414A` | 轨迹格式标识 'TRAJ'。**注意落盘字节序为 `4A 41 52 54`（"JART"）**，即把 `'TRAJ'` 的字符码按大端组合成 u32 后再小端写出；解析端比对的是数值 `0x5452414A`（见 `index.html:210`） |
| 4 | `version` | u32 | `2` | 格式版本 |
| 8 | `fps` | u32 | `60` | 帧率，来自脚本常量 `FPS` |
| 12 | `total_frames` | u32 | `720` | 总帧数（=12 s），来自脚本常量 `TOTAL_FRAMES` |
| 16 | `object_count` | u32 | `3` | 物体数（机械臂 + 苹果 + 盒子） |
| 20 | `attach_count` | u32 | `2` | 挂载事件数 |
| 24 | `index_offset` | u32 | `32` | Index 区起始偏移，恒为 32 |
| 28 | `attach_offset` | u32 | `296` | Attach 区起始偏移 |

Data 区起始偏移不写入头部，由 `attach_offset + 16 × attach_count` 推出（样例 = 328）。

---

## 3. Index 区（每物体一条记录）

每条记录 = 对象头 + 默认位姿 + 段表：

### 3.1 对象头 `struct.pack('<IIHH', ...)`，12 字节

| 字段 | 类型 | 样例（物体 1） | 含义 |
|------|------|----------------|------|
| `object_id` | u32 | `1` | 物体唯一 ID，取自 `scene.json` |
| `parent_id` | u32 | `4294967295` | 初始父节点 ID，即 `scene.json` 的 `worldId`；`0xFFFFFFFF` 表示挂在世界（场景根）下 |
| `pose_dim` | u16 | `7` | 单帧姿态的 float 分量个数 |
| `segment_count` | u16 | `9` | 本物体的段数，0 表示全程使用默认位姿 |

> `pose_dim = 7` 有两种语义，由 `object_id` 是否为机械臂（`scene.robot.id`）区分：
> - **机械臂**：6 个关节角（rad）+ 第 7 个夹爪开合度（0.0 张开 / `gripper.graspValue`=0.72 闭合）
> - **普通物体**：位置 `x,y,z`（m）+ 四元数 `qx,qy,qz,qw`，注意这里的位置和旋转都是相对于父物体的局部位姿

### 3.2 默认位姿，`pose_dim × 4 = 28` 字节（float32）

静止/无数据帧的回退值：机械臂为 `homeJoints + 夹爪张开`，物体为 `scene.json` 中的 `position + quaternion`。

### 3.3 段表，每段 `struct.pack('<IIII', ...)` 16 字节

| 字段 | 类型 | 含义 |
|------|------|------|
| `start_frame` | u32 | 段起始帧号（0-based，含） |
| `frame_count` | u32 | 段帧数，实际覆盖 `[start, start+count-1]` |
| `data_offset` | u32 | 段数据在文件中的**绝对字节偏移**，`段长度 = frame_count × pose_dim × 4` |
| `step_count` | u32 | 操作步骤编号：0 空闲 / 1 抓取 / 2 搬运 / 3 放置 |

段**允许不连续**（`start_frame` 单调递增，但不要求首尾相接）；空隙帧沿用前一段末帧姿态，一个步骤可对应多段。

---

## 4. Attach 区（每条 16 字节）

`struct.pack('<IIII', frame, child_id, parent_id, 0)`

| 字段 | 类型 | 含义 |
|------|------|------|
| `frame` | u32 | 生效帧号（在该帧及之后生效） |
| `child_id` | u32 | 被重新挂载的物体 ID |
| `parent_id` | u32 | 新父节点 ID；`0xFFFFFFFF` = 场景根 |
| `reserved` | u32 | 保留，写 0 对齐到 16 B |

样例事件：

| 帧 | child | parent | 语义 |
|----|-------|--------|------|
| 340 | 2 苹果 | 1 机械臂 | 夹爪闭合后苹果挂到 TCP，随臂运动 |
| 530 | 2 苹果 | 3 盒子 | 下放到位后苹果改挂盒子，臂离开 |

挂载事件按帧递增写入；播放端每次跳帧按 `frame ≤ f` 重放事件即可还原层级状态。

---

## 5. Data 区

`float32` 一维数组，按 `帧 × pose_dim` 排列，无行对齐填充。样例为机械臂 9 段共
420 帧 × 7 × 4 B = 11760 B（328 ~ 12088）。各段帧内值由 `build_segment()` 在相邻关键姿态间做 `smoothstep` 插值（`s²(3−2s)`）生成。

## 7. 解析要点与约束

1. **全小端**：`new DataView(buf)` 的每个读取都传 `littleEndian = true`。
2. **magic 校验**用数值 `0x5452414A`，不要用 ASCII `"TRAJ"` 直接比对字节。
3. **`pose_dim` 是唯一的帧步长来源**：段字节长度 = `frame_count × pose_dim × 4`，不要假设固定 7。
4. **`data_offset` 是绝对偏移**：`new Float32Array(buf, seg.dataOffset, ...)` 要求 4 字节对齐，头部/索引/挂载区的累计长度天然满足（32 / 12+4·dim / 16）。
5. **段间空隙合法**：不可假设段连续，也不可假设 `start_frame` 从 0 开始；空隙帧语义 = 沿用上一段末帧。
6. **`step_count` 是步骤号而非段号**：进步骤可跨多段，同一步骤的相邻段之间空隙也应归入该步骤。
7. **`parent_id = 0xFFFFFFFF` 表示世界根**，其值来自 `scene.json` 的 `worldId`，改动该值会影响挂载解析。
8. **容量变化时只需重算偏移**：Header 中 `attach_offset` 与派生的 Data 起始偏移由脚本自动计算，字段顺序与结构不变即可向后兼容。
