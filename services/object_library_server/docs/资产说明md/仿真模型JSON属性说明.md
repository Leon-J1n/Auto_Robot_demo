# 仿真资产 JSON 属性单独说明（.json）

本文从robots和models文件夹内各模型属性 JSON 的字段顺序说明语义、几何、物理、抓取和 URDF 专用配置。内容来自当前交付目录的属性文件，字段和示例按现有资产整理。

<a id="metadata"></a>

## 1　模型属性 JSON

各模型`<名称>.json` 的前四项依次是 `semantic_properties`、`geometric_properties`、`physical_properties`、`grasp_properties`。机械臂随后单独有记录布局配置，然后所有有 URDF 的资产最后记录 `robot_driver`。命名和标签由编目者填写，几何边界从模型计算，抓取位姿由作者采集。物理参数的来源需逐项区分。

### 1.1　`semantic_properties`　资产身份与使用语义

| 字段（按顺序） | 类型 | 含义与填写依据 |
| --- | --- | --- |
| `object_name` | 字符串 | 资产名，也是主要文件的名称前缀。在 `models` 中表达“这是什么物体”，允许同名，例如 `basket` 对应 4、12 两个 ID。在 `robots` 中通常写设备型号或配件名，如 `ur5`、`d455`。人为根据模型主观确定 |
| `object_id` | 整数 | 当前类别内的资产编号，由编目者分配。与数字目录名、索引记录对应。场景中的实例另有自己的编号。 人为按id顺序确定|
| `deformable` | 布尔值 | 该物体是否被标注为可变形。如布料可变形值为true，根据模型确定。 |
| `scalable` | 布尔值 | 是否允许在场景中调整模型比例。人为根据模型主观确定，可选倍率另见 `physical_properties.scale`。 |
| `interactable` | 布尔值 | 是否为可交互的对象。若为则在运动时可先到达物体附近，人为根据模型主观确定供技能skill使用|
| `tag` | 字符串 | 模型描述标签，如 `"red"`。多标签在同一字符串中用英文逗号分隔，如 `"robotiq,gripper"`。人为根据模型主观确定供agent使用 |
| `can_place` | 布尔值 | **仅 `models` 具有。** 表示该物体能否作为容纳另一个物体的放置目标。`true` 允许，`false` 禁止。例如 17 号托盘为 `true`，1 号苹果为 `false`。根据模型确定供agent使用。 |

### 1.2　`geometric_properties`　模型自身坐标系中的边界

| 字段（按顺序） | 类型 | 含义与填写依据 |
| --- | --- | --- |
| `AABB` | 长度为 6 的数值数组，单位 **m**。 | 顺序固定为 **`[xmax, xmin, ymax, ymin, zmax, zmin]`**，即 +X、−X、+Y、−Y、+Z、−Z 方向对应的有符号坐标边界。保留坐标值的正负号。根据模型obj确定 |
| `placement_quaternion_xyzw` | 模型在世界坐标系中的放置位姿，决定模型在前端显示的姿态，主要提供给前端使用，人为设置，默认0001|值为xyzw的四元数

| 类型 | 计算方法 |
| --- | --- |
| OBJ | 在 OBJ 自身的顶点坐标系中，对实际几何分别取 X、Y、Z 最大值和最小值。以交付尺寸、米为单位。 |
| URDF | 在模型参考构型下，将全部 **`visual` 几何**（网格、盒体、圆柱等）变换到 URDF 根连杆坐标系，合并后取极值。计算包括网格缩放、`visual/origin`、各级关节变换和固定旋转关节。|

JSON 保存单个参考构型的边界。例如 25 号抽屉、1 号 UR5 和 2 号夹爪的现有数值都对应 URDF 关节零位。机械臂进入场景时可有另一组初始关节角。开门、伸抽屉、弯曲机械臂后的实时边界应按相应关节状态计算。修改模型自身原点或轴向后要重新计算本地 AABB。仅在场景中平移或转动整个实例时，资产仍使用原来的本地 AABB。

### 1.3　`physical_properties`　物理参数与缩放范围

| 字段（按顺序） | 类型、单位 | 含义与来源 |
| --- | --- | --- |
| `is_static` | 布尔值，放在 `physical_properties` 第一项。 | `true` 表示仿真期间根部固定，不受重力、碰撞或外力影响而移动，但仍参与碰撞；`false` 表示允许运动，不代表当前一定在移动。缺失时默认 `false`。关节资产只固定根部，内部关节仍由 `robot_driver` 控制；编辑阶段仍可调整摆放。 |
| `mass_kg` | 数值，kg | 整个资产的质量。可与 URDF 各连杆 `inertial/mass` 之和对照。OBJ 网格本身不提供质量。人为参考urdf主观确定并通过夹取测试修正 |
| `friction.format` | 字符串 | 顺序声明，现值为 `"[sliding, torsional, rolling]"`。模型的摩擦系数声明。 |
| `friction.values` | 三个数值 | 依次为滑动、绕接触法线扭转、滚动摩擦参数。参考其他仿真通常设定人为设置并通过夹取测试修正 |
| `restitution` | 数值，无量纲 | 恢复系数，描述碰撞回弹程度。通常取 0 到 1，参考其他仿真通常设定人为设置并通过夹取测试修正。具体接触求解器决定如何使用它。 |
| `scale` | 两个数值，无量纲 | 允许的统一缩放倍率 `[最小倍率, 最大倍率]`。例如抽屉的 `[1.0, 2.5]`。结合 `scalable` 读取。`[1.0, 1.0]` 只给出原尺寸。场景实例的三轴缩放是另一个字段。 人为根据模型主观设置。 |

模型物理属性提供资产默认值；场景 `PhysicalProperties` 组件可按实例覆盖 `is_static`、`mass_kg`、`friction`、`restitution`。未覆盖字段继承资产默认值。`scale` 仍表示资产允许缩放范围，实例缩放使用 `Transform.scale`。

### 1.4　`grasp_properties`　提前采集的抓取位姿

`pose_count` 是已记录的抓取方案数，最多为3，应等于 `poses` 的长度。`poses` 是数组，每个元素有 **10 个数**。没有位姿时填写 `"pose_count": 0` 和 `"poses": []`。当前机器人与配件均保留这一空块。场景物体也允许为空，例如 29 号桌子。全部内容通过仿真平台测试采集。

| 位置（从 1 开始） | 内容 | 参考系、单位与意义 |
| --- | --- | --- |
| 1–3 | `x, y, z` | 夹爪抓取中心 TCP 在**物体自身坐标系**中的目标坐标，单位 m。 |
| 4–6 | `rx, ry, rz` | TCP 相对物体的目标朝向，单位 rad。项目抓取工具按 `Rz(rz) × Ry(ry) × Rx(rx)` 组合旋转。 |
| 7–9 | `tolerance_axis_x, tolerance_axis_y, tolerance_axis_z` | 允许角度偏差的轴，以单位方向向量表示，无量纲。例如 `[0, 1, 0]` 指定 Y 轴。 |
| 10 | `tolerance_radius` | 围绕所选轴的角度容差半径，单位 rad。0 表示该项没有额外角度余量。 |

## 2　机械臂与关节资产的专用字段

### 2.1　`arm_configuration`、`scene_one_arm`、`scene_two_arm`

这组字段位于机械臂属性文件的 `grasp_properties` 之后。当前有且仅 7 份机械臂资产使用它们。

| 字段 | 类型与适用资产 | 填写含义 |
| --- | --- | --- |
| `arm_configuration` | 字符串。机械臂 1、5、6、7、8、9、13 均有 | 机械臂结构类型标识。当前七份均存为 `"piper"`，包括 UR5 和 PR2。供ik求解器使用区分不同构型机械臂，当前未确定分为几种构型。 |
| `scene_one_arm` | 对象数组。上述七份均有，每份一项 | 场景摆放一台机器人时的基座布局预设。一台 PR2 自带左右两条臂，因此也用单台布局。人为根据场景布局采集 |
| `scene_two_arm` | 对象数组。机械臂 1、5、6、7、8、9 有，每份两项 | 在同一场景放两台该型机械臂时，分别给出两台的摆放预设。PR2 元数据只提供 `scene_one_arm`。人为根据场景布局采集 |

两个布局数组的每个元素都按以下顺序填写，没有时用空代替不可省略。

| 字段 | 类型与单位 | 含义 |
| --- | --- | --- |
| `robot_pose_percent_compared_to_table_length_center` | 三个有符号数，百分比 | 机械臂基座原点相对桌面靠近机械臂一侧的**长边中点**的位置比例。因为桌子世界坐标系必须为0000001，所以桌子姿态固定，通过桌子确定机械臂位姿，选取桌子长边中点参考点，值为（机械臂基底世界坐标系值-桌长边中点世界坐标系值）/桌长。如桌高0.6，则桌长边中点世界坐标系z为0.6，机械臂基底世界坐标系z为0.45，则（0.45-0.6）/0.6=-0.25便是z值。|
| `has_pedestal` | 布尔值 | 此布局是否使用单独的底座资产。为空则放到桌子上或者放在地上，人为根据机械臂类型确定 |
| `pedestal_id` | 整数 | 使用底座时填写，引用 `robots` 中的底座 ID。当前仅为 4。 |
| `pedestal_scale` | 三个数，无量纲 | 底座沿自身 X、Y、Z 的缩放倍率。因为机械臂底座高度不同，所以通过缩放底座满足各机械臂需求，当前 Piper 和 PR2 的单台布局取 `has_pedestal: false`，省略底座 ID 和缩放。 人为根据机械臂基底位姿确定|

**布局换算示例。** 按交付桌子坐标约定，原点为底面中心，+X 沿长边，靠近机械臂的一侧在 −Y。设长宽高为 `L, W, H`，布局比例为 `[a, b, c]`，即可求得基座在桌子坐标系中的位置。

```text
[0, -W/2, H] + [a × L, b × W, c × H]
```

UR5 单台布局取 `[0, -0.3, -0.166666666667]`，桌子尺寸取 `[1.5, 0.75, 0.6]` m，得到基座位置约 `[0, -0.6, 0.5]` m。这个值是资产的摆放预设。读取一个已经创建的场景时，应使用该实例的 `Transform`。

### 2.2　`robot_driver.properties`　关节与安装接口

当前 **16 份 URDF 资产**都有此块，包括 6 个场景物体、7 台机械臂、3 个夹持设备。OBJ 资产省略此块。以下均为 `robot_driver.properties` 的子字段。

| 字段（按顺序） | 类型与单位 | 含义与来源 |
| --- | --- | --- |
| `role` | 字符串 | 项目指定的驱动角色。可自己驱动的值为arm，如机械臂，夹爪，否则为passive，如柜子，抽屉。当前 `models` 的 URDF 均为 `"passive"`，`robots` 的 URDF 均为 `"arm"`，指式夹爪和真空夹具也使用后者。根据模型确定。 |
| `joint_sequence` | 有序的关节名数组 | 可独立驱动的关节在urdf里的真实名称及其顺序，可供操作物体，控制机械臂，夹爪时使用。根据模型urdf确定 |
| `joint_limits` | 按关节名索引的对象，值为 `[下限, 上限]` | 与序列逐关节对应。旋转关节用 rad，直线关节用 m。有限行程以 URDF 的 `limit.lower/upper` 为依据。连续转动关节没有机械止挡时，本项目可用 `[−π, π]` 表示约定的一圈。 |
| `initial_joint_positions_rad` | 按关节名索引的数值对象 | 选定的初始构型。旋转关节用 rad。**直线关节仍用 m**，即使字段名带 `_rad`。初始值应在采用的限位范围内。 主要用于场景初始化时机械臂或夹爪姿态，人为主观在仿真平台采集|
| `available_connect_joints` | 关节名数组 | 可安装子设备的末端对应关节，在 URDF 中按名称定位。目前仅机械臂有，为机械臂可链接夹爪的关节，根据模型urdf确定。 |
| `available_connect_link` | 连杆名数组 | 同上，每个连接端实际使用的**父连杆**，名称来自 URDF。字段名用单数 `link`，值为数组。 |
| `position` | 三维坐标数组的数组，m | 各安装接口原点**相对对应父连杆**的平移，由于夹爪底部通常为圆柱形，目前设计夹爪坐标系必须在夹爪底部表面中心，所以不同机械臂确定一个安装位姿，则所有夹爪皆可通用。即使只有一个可链接处，也要统一写成二元数组 `[[x,y,z]]`。 |
| `quaternion_xyzw` | 四元数数组的数组，无量纲 | 对应安装接口相对父连杆的朝向，顺序为 `[x,y,z,w]`。每项使用单位四元数，恒等旋转为 `[0,0,0,1]`。 |
| `robot_attachment.properties.child_link` | 连杆名数组 | 设备作为被安装的一方时，指定由自身哪条连杆对接父设备。名称取自子设备 URDF，目前只有夹爪具备，为夹爪链接机械臂时使用。当前指式夹爪和真空夹具各列一个。 |

`available_connect_joints`、`available_connect_link`、`position`、`quaternion_xyzw` 按相同下标对应。读取第一个接口时，应一起取四个数组的第一项。没有可对外提供的连接端时，这四项通常均为 `[]`。
