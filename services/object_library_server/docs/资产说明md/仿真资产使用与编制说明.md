## 1　文件组织与命名

### 1.1　资产类别和编号

一个资产由**目录类别和数字 ID** 共同标识。例如 `models/1` 是苹果，`robots/1` 是 UR5，`scenes/1` 是空桌场景。三个目录分别编号。模型资产以 `<名称>_files.json` 为文件清单，以清单中的 `path` 为加载入口。

| 资产 | OBJ 入口 | URDF 入口 |
| --- | --- | --- |
| `models` 场景物体 | 25 个。编号 1–24、26，包含苹果、笔、篮子等 | 6 个。25 抽屉、27 按钮、28 柜子、29 桌子、30 瓶子、31 微波炉 |
| `robots` 机器人及配件 | 4 个。3、11 为相机，4 为底座，14 为白色背景板 | 10 个。1、5–9、13 为机械臂或双臂机器人，2、10 为指式夹爪，12 为真空夹具 |

名称沿用包内的小写英文写法，多词用下划线连接，例如 `sugar_box`、`robotiq_2f85`。同一资产的入口、属性、清单和缩略图共享名称前缀。同类物体可以重名，例如 `models/5/pen.json` 与 `models/6/pen.json` 是两份独立资产。

### 1.2　OBJ 资产以单份网格为入口

以 `models/1/` 为例，苹果的六个文件分别承担以下职责。

| 实际文件 | 命名规则 | 内容和用途 |
| --- | --- | --- |
| `apple.obj` | `<名称>.obj` | 几何入口。保存顶点、面和材质分组，可包含法线及纹理坐标。OBJ 顶点所在坐标系就是该资产的本地坐标系。 |
| `apple.mtl` | `<名称>.mtl` | 材质表。OBJ 的 `mtllib` 引用它，`usemtl` 选择材质。纯色由 `Kd` 等材质参数给出。 |
| `apple.png` | 本例为 `<名称>.png` | 表面贴图。MTL 的 `map_Kd` 指向它，非必有文件，没有时在mtl里面直接定义模型外表。渲染器按 OBJ 的 UV 坐标贴到表面。 |
| `apple.json` | `<名称>.json` | 模型属性，包括语义、几何、物理和抓取信息，需要提前采集的信息皆可放入。 |
| `apple_files.json` | `<名称>_files.json` | 文件清单，声明加载入口和需要一起分发的依赖，供前端使用。 |
| `apple_thumbnail.png` | `<名称>_thumbnail.png` | 资产列表中供人辨认模型的 128 × 128 像素缩略图，在前端可视化用。 |

纯色模型可用 OBJ 和 MTL 表达外观。例如 `robots/4` 的底座只有五个文件，没有表面贴图。当前 `models` 的 OBJ 目录实际均有六个文件，但文件存在与材质引用是两件事。18 号茶几目录有 `coffee_table.png`，其 MTL 使用纯色，清单的 `reference` 只列 `coffee_table.mtl`。编制清单时，应沿 OBJ → MTL → 贴图的引用关系填写。

### 1.3　URDF 资产以连杆和关节描述为入口

以 `robots/1/` 的 UR5 为例。目录顶层有四个文件和一个网格目录。

```text
robots/1/
├── ur5.urdf
├── ur5.json
├── ur5_files.json
├── ur5_thumbnail.png
└── ur5_meshes/
    ├── base_0.obj
    ├── base_0.mtl
    └── … 其余连杆网格与材质
```

| 文件或目录 | 应保存的内容 |
| --- | --- |
| `<名称>.urdf` |定义如何链接多个 OBJ，描述机器人或关节物体的结构。每个 `link` 可含显示几何 `visual`。 |
| `<名称>_meshes/` | URDF 引用的部件网格及配套材质、贴图。部件名与目录层级按 URDF、OBJ 和 MTL 的相对路径保留。可按部件嵌套，如抽屉的 `drawer_meshes/Nightstand0017/part_00/`。|
| `<名称>.json` | 同前面obj类型json文件，但多了urdf的部分属性，整份资产的模型属性。关节控制和安装接口由这里的 `robot_driver` 提供给场景系统。 |
| `<名称>_files.json` | 同前面obj类型_files.json文件，列出 URDF 入口、属性文件、缩略图和部件依赖。UR5 的清单列出 40 个 OBJ／MTL 依赖。 |
| `<名称>_thumbnail.png` |同前面obj类型缩放图，整份资产的缩略图。每个物体一张。|

URDF 也可用于只有固定关节的组合物体，例如 29 号桌子。部件网格、材质和贴图的数量随资产而变。部分目录另附 `LICENSE.txt`，交付时应保留来源许可。

## 2　模型各文件内容分别介绍


### 2.1　模型内文件清单（_files.json）

模型和机器人共用以下清单字段，路径均相对于当前数字 ID 目录。

| 清单包含以下字段 | 类型与填写规则 |
| --- | --- |
| `is_on_cos` | 布尔值，标识资源是否存放在 COS 对象存储。此交付包使用本地文件，值为 `false`。 |
| `metadata` | 字符串，模型属性 JSON 的相对路径，如 `ur5.json`。 |
| `path` | 字符串，主入口的相对路径，区分是否为urdf，如 `apple.obj` 或 `ur5.urdf`。 |
| `thumbnail` | 字符串，目录缩略图的相对路径，如 `ur5_thumbnail.png`。 |
| `reference` | 字符串数组，逐项列出加载入口所需的附属文件。含子目录时写完整相对路径，如 `ur5_meshes/base_0.obj`。 |

### 2.2　模型缩放图（_thumbnail.png）
模型和机器人缩略图均为 **128 × 128 像素、白色背景**。物体缩略图按既定拍摄要求，将相机放在模型自身的 **−Y 一侧且高于物体**，朝物体中心俯拍约 45°。此时视线的水平分量沿 +Y。画面保留完整轮廓并适当留白。同组设备复用相近构图，例如两款相机的缩略图。像素尺寸是文件属性，拍摄角度和物体占比是制作要求,真正的目的是为了让缩放图展示的是模型最可观的一面，能直接说明这个物体是什么的一面。

### 2.3　模型属性 JSON

模型属性 JSON 的完整字段说明已单独整理在(仿真资产JSON属性说明.md)中。

## 3　三个目录索引

### 3.1　`models/model_index.json`　按物体名称或编号查找

根节点是 JSON 对象，由五张对照表组成。以 ID 为键时，JSON 键是带引号的字符串。`by_name` 数组中的 ID 则是整数。

| 字段（按顺序） | 数据形状 | 用途与现有例子 |
| --- | --- | --- |
| `by_name` | 名称 → ID 数组 | 按名称查全部候选。不同模型可同名，根据id区分，例如 `"basket": [4, 12]`。选择具体资产时继续使用选中的 ID。 |
| `by_id` | ID 字符串 → 名称 | 反查名称。例如 `"12": "basket"`，对应目录 `models/12/`。 |
| `category` | ID 字符串 → 分类字符串 | 用于列表分组，如 `模型.抓取物`、`模型.放置物`。人为主观分类 |
| `thumbnail` | ID 字符串 → 缩略图相对路径 | 路径相对于 `models/`。12 号为 `12/basket_thumbnail.png`。 |
| `no_display` | ID 字符串 → 布尔值 | `true` 表示在前端资产列表中隐藏，`false` 表示可展示。场景仍可按 ID 引用已隐藏的资产，例如 29 号桌子。人为主观设置|


### 3.2　`robots/robot_index.json`　按设备名称或编号查找

根节点同样是对象，共四张对照表，基本一致。

| 字段（按顺序） | 数据形状 | 用途与现有例子 |
| --- | --- | --- |
| `by_name` | 名称 → ID 数组 | 当前每种设备名只有一个 ID，仍保留数组形式。例如 `"ur5": [1]`。 |
| `by_id` | ID 字符串 → 名称 | 例如 `"1": "ur5"`、`"11": "d455"`。 |
| `category` | ID 字符串 → 分类字符串 | 记录目录分类，如 `机械臂.UR`、`机械臂.夹爪`、`机械臂.摄像机`、`机械臂.底座`、`机械臂.背景`。 |
| `thumbnail` | ID 字符串 → 缩略图相对路径 | 同上 |
| `no_display` | ID 字符串 → 布尔值 | 列表显示开关，含义同物体索引。当前 4 号底座、13 号 PR2、14 号背景板为 `true`。 |


### 3.3　`scenes/scene_index.json`　按场景和任务查找

根节点是**数组**，每一项描述一个场景。数组下标与场景 ID 分开使用，查找时匹配记录中的 `id`。

| 字段（按顺序） | 类型 | 含义与来源 |
| --- | --- | --- |
| `id` | 整数 | 场景作者分配的编号，对应 `scenes/<id>/` 和场景 JSON 的 `scene_id`。 |
| `name` | 字符串 | 场景名称，与场景 JSON 的 `scene_name` 及主要文件前缀对应。 |
| `task_category` | 字符串 | 任务分类。当前使用空白、抓取、开柜、旋转扭动、推拉。多个场景可以同类。 |
| `no_display` | 布尔值 | 列表显示开关。当前七个场景均为 `false`。 |

## 4　编制与定稿顺序

1. **定身份。** 先选 `models`、`robots` 或 `scenes`，在该目录分配数字 ID，确定名称。物体同名时保留各自的 ID 目录。改名时同步处理入口、属性、清单、缩略图、索引名称以及文件内部使用旧名的网格路径。
2. **定几何和外观。** 单网格资产走 OBJ。需要连杆、关节或分部件碰撞描述时，以 URDF 为入口。先确定模型本地原点、轴向和米制尺寸，再整理材质、贴图及其相对路径，最后制作缩略图。
3. **填模型属性。** 按仿真资产 JSON 属性说明的字段顺序编目。AABB 从最终版几何计算。物理参数按采用的资料填写。抓取位姿在最终模型坐标系内采集。改变原点或轴向时，AABB、已采集的局部抓取位姿及相关安装变换需一起复核。
4. **补布局和接口。** 有 URDF 时填写驱动块。按实际关节类型选取单位，使用 URDF 中的关节名、连杆名。机械臂另外填写布局预设。夹爪填写自身的安装连杆。四元数按 `[x,y,z,w]` 记录。
5. **登记索引并交付。** `models` 与 `robots` 同步登记正反向名称映射、分类和显示标志。物体索引另登记缩略图路径。`scenes` 增加一条场景记录。交付前从索引走一遍“数字目录 → 文件清单 → 入口与依赖”，并查看缩略图、属性 ID 和关节接口是否与该资产对应。
