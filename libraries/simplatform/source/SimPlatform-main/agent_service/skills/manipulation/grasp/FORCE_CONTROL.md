# 夹爪执行器力控制

`grasp_force`（默认 40）和 `hold_force`（默认 40）的单位是 N，表示两侧指垫法向力之和的近似预算，范围为 0–40。
命令参数可以覆盖这两个值。闭合阶段使用 `grasp_force`，抓取成功后立即切换为 `hold_force`。

Live 接口将每个夹爪关节的有限力矩上限传到 MuJoCo 的位置伺服。
力矩有限时，接触可以阻止手指抵达目标；程序不会再强行写入闭合位置。
后续机械臂 move 保留手指的闭合目标和力矩上限，不会用受阻后的实际位置覆盖目标。
release 使用有限力矩打开手指，并将后续保持目标切换到张开位置。

换算沿用现有线性开口模型：全行程 0.085 m 对应驱动角 0.8 rad。
总广义力矩预算为 `F_total / 2 × 0.085 / 0.8` Nm，均分到六个耦合关节的执行器。
因此 20 N 对应每个关节约 0.1771 Nm，10 N 对应约 0.0885 Nm。
这避免将全部预算重复施加六次，但它是传动关系的近似，不是经过标定的力传感器闭环。
上限约束伺服反馈力矩；MuJoCo 后端原有的重力/偏置补偿单独叠加，不包含在此上限内。

返回状态中的 `force` 保留兼容含义，并通过 `force_source=commanded_total_jaw_force` 明确标记为命令值，不能当作 MuJoCo 实测接触力。
抓取成功读取 MuJoCo 的有效接触约束及正法向力，识别左右末端手指（指腹、spring/follower 支撑连杆）。
掌部、驱动连杆和桌面接触不计为夹持。FCL 的三角面碰撞查询仍用于路径规划，不再用于判定真实夹持。

`post_contact_step` 仍控制接触后的目标闭合增量，配置文件及用户数值保持不变。
力矩上限是上限，不保证一定达到对应夹紧力；目标闭合增量不足时，应结合接触状态调整。
本次接口需要重新构建平台并重启平台进程和 Agent 服务后使用。

## 物理执行与验收

MuJoCo 使用隐式速度伺服执行手指力矩上限；机械臂也在物理步内执行伺服，不再在求解后覆盖受控关节的位置。
机械臂速度反馈增益为 100，手指为 1，避免极高增益破坏夹持接触。接触使用椭圆摩擦锥、较高摩擦约束阻抗和无滑移后处理。
源 URDF 中的 mimic 关系转为 MuJoCo 关节等式约束，受载时仍保持连杆联动。此功能要求构建启用 urdfdom，且场景引用的 URDF 文件可读取。
碰撞子节点不再按默认密度额外增加刚体质量，场景中设置的质量因此能正确应用。

闭合停止依据每个实际仿真步后的双侧接触；接触中断会重新计数。`post_contact_step` 不变，目标仍以 0.5 秒全行程的速度推进。
切换到 `hold_force` 后，`settle_time`（默认 0.3 秒）会推进真实仿真并保持原闭合目标，非实时模式也生效。这是停止推进闭合目标后的受力稳定时间，不会增加接触后继续闭合的步数。

可重复验收（配置 `SIM_PLATFORM_LIBRARY`、`SIM_PLUGIN_DIR` 和项目/Python SDK 的 `PYTHONPATH` 后运行）：

```powershell
python -m agent_service.tools.verify_gripper_carry --scene <UR5e_Robotiq场景.simstate> --catalog-pose --report <报告.json>
```

工具使用独立平台实例、真实棒球网格、0.2 kg、重力与摩擦接触，执行 grasp、抬升 10 cm、横移 10 cm、保持 1 秒和 release。
相对漂移超过 10 mm、连续采样接触缺失超过 0.1 秒、阶段结束时失去双侧接触、未跟随移动或松开后不下落都会使测试失败；不绑定物体、不调用 Qwen。
报告保留所有接触缺失次数：求解器接触切换允许短暂间断，但不能据此声称全程无滑移。
持物的定时轨迹以 2 ms 仿真步插值控制目标；timeline 仍按原定帧率采集。
