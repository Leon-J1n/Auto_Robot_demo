# 圆弧执行与收敛判定

圆弧继续使用 `config/global.json` / 显式请求中的关节速度、加速度比例。
优化不改变物理步长、物体约束、夹爪力或资产。

## 时间参数化

- 保存原始等角度圆弧 IK 点，用这些点构建关节曲线；碰撞检测补入的直线插值点
  不再作为额外的曲线拟合约束。每次构建后仍检查插值路径的碰撞和圆弧位姿偏差。
- 未指定 jerk 上限时，圆弧采用局部速度曲线。对每个三次多项式小区间计算一、二阶
  导数的界限，将加速度预算分别分给曲率项和切向加速度项，再前向/反向传播可达速度。
  起点、终点的路径速度为零。局部弯曲不会强制整段按最慢位置缩放。
- 保留默认 `corner_slowdown=0.25` 裕量；显式值继续生效。指定 `max_jerk` 时保留原有
  五次时间曲线及 jerk 约束，不把 jerk 设置静默忽略。
- 局部时间参数化的圆弧执行使用位置执行器的 `kv/kp * q_dot_ref` 速度前馈，减少
  执行器按零目标速度阻尼造成的跟踪滞后。前馈经过执行器控制及力限制，不写入真实 qpos。
- 报告保留时间曲线类型、原始/加密点数、参考轨迹速度/加速度峰值和圆弧插值位姿误差。

## 完成与失抓

参考走完后，需要同时满足低关节速度、TCP 位姿精度以及连续 0.1 秒稳定时间。
普通运动保留 0.001 rad 关节误差上限；已有物理抓持时允许不超过 0.002 rad 的微小
静态负载偏差，但仍要求 TCP 位置误差不超过 2 mm、姿态误差不超过 0.02 rad，
以及有效双侧接触。用户指定更严格的 TCP 容差时取更严格的值。

接触监测按物理步进行，独立于轨迹导出 FPS。单侧接触短暂抖动的原始记录不隐藏，
通过 `contact_diagnostics` 报告发生次数和最长时长。连续失去双侧接触达到 0.1 秒，
或接触丢失同时伴随超过 5 mm / 0.05 rad 的相对滑移，则立即终止运动并返回
`GRASP_FAILED`，push/pull 不会在这种失败后继续释放夹爪。

`EXECUTION_TIMEOUT` 的 `error.details.reason` 区分：

- `wall_time_limit`：真实执行耗时达到请求的 timeout。
- `goal_not_converged`：参考轨迹走完后，额外等待 5 秒仿真时间仍未满足完成条件。

超时报告保留规划轨迹、计划时长、实际耗时、关节/TCP 误差、接触与稳定时间，
不再仅给出一个关节误差数值。
